## 1. 查询与分页

### 1.1 入口选择

| 场景 | 入口 | 依据 |
| --- | --- | --- |
| 单键查询 | `GetAsync<T>(key)` | 直查槽 + 单行物化；比 `From<T>().Where(Id==x).FirstOrDefaultAsync()` 省约 880 B/操作、快 25~30%（2026-10-01 探针，3000 次摊销） |
| 带过滤条件 | `From<T>()` 链式 | 构建器显式出 SQL，可用 `AsDryRun` 预览 |
| 聚合 | `CountAsync` / `SumAsync` / `AvgAsync` / `MaxAsync` / `MinAsync` | 软删除与租户过滤自动生效 |
| 大键集过滤 | `WhereIn` / `WhereNotIn` | 自动按 500 键分批，规避参数上限 |
| 深翻页 | `ToPageAsync` | Keyset 游标，单往返 |
| 行数不可控 | `QueryAsyncEnumerable` / `ForEachAsync` | 峰值内存 O(1) |

`From<T>()` 返回 `struct QueryBuilder<T>`，链式 `.Where()` / `.OrderBy()` / `.Take()` / `.Skip()` / `.Select()` / `.GroupBy()` / `.Having()` / `.Include()` / `.ThenInclude()`；另有 `InnerJoin` / `LeftJoin` / `RightJoin`、CTE（`.With()`）、窗口函数、悲观锁（`ForUpdate` / `ForShare`）、`AsDryRun`（预览 SQL + 参数）、`WithCache`、`WithMetrics` / `WithTracing`。

```csharp
var page = await db.From<Order>()
    .Where($"status = {OrderStatus.Paid}")
    .OrderBy(o => o.CreatedAt)
    .Skip(20).Take(10)
    .ToListAsync();
```

### 1.2 Keyset 分页

```csharp
// 第一页：按 CreatedAt 降序取 20 行
var (rows, total) = await db.From<Order>().ToPageAsync(20, o => o.CreatedAt);

// 下一页：上一页末行的排序值作游标
var next = await db.From<Order>().ToPageAsync(20, o => o.CreatedAt, lastValue: rows[^1].CreatedAt);
```

契约三条（源码级）：① 审计拦截器看不到 COUNT SQL；② builder 上已设的 `Skip()` 被忽略（键集分页不吃 OFFSET 语义）；③ 先行的 `Take()` 被 `pageSize` 覆写。PG 上 COUNT 与页 SELECT 打包为单往返。

### 1.3 聚合

```csharp
long count     = await db.CountAsync<Order>($"status = {OrderStatus.Paid}");
decimal sum    = await db.SumAsync<Order>(o => o.Amount);
double avg     = await db.AvgAsync<Order>(o => o.Amount);
DateTime? last = await db.MaxAsync<Order, DateTime>(o => o.CreatedAt);
```

### 1.4 并发读

先声明并行读租约，作用域内各自拿独立连接（上限 8）：

```csharp
await using (db.ForParallelReads())
{
    await Task.WhenAll(db.From<User>().ToListAsync(), db.From<Order>().ToListAsync());
}
```

> 作用域内 `GetAsync` 与查询族走局部读连接池；与在飞只读操作并发的写 / 事务 / Bulk 会被单活动门禁拒绝。

## 2. 流式与大结果集

行数不可控时不要 `ToListAsync`：

```csharp
// 回调式：逐行消费，不建列表
await db.From<Order>().ForEachAsync(order => sink.Write(order));

// 异步枚举式：消费原生 SQL 结果
await foreach (var order in db.QueryAsyncEnumerable<Order>($"SELECT * FROM orders WHERE status = {status}"))
    sink.Write(order);
```

多结果集用 `GridReader` 一次往返取多表：

```csharp
await using var grid = await db.From<User>()
    .QueryMultipleAsync($"SELECT * FROM users WHERE id = {userId}; SELECT * FROM orders WHERE user_id = {userId}");
var user = await grid.ReadFirstAsync<User>();
var orders = await grid.ReadAsync<Order>().ToListAsync();
```

**GC 模式**：高吞吐服务端开 `<ServerGarbageCollection>true</ServerGarbageCollection>`；容器配 `GarbageCollectionHeapHardLimit` 防 OOM。客户端/小内存保持 Workstation 默认。

## 3. 事务与弹性

### 3.1 函数式事务（自动 commit / rollback）

```csharp
await db.WithTransaction(async ct =>
{
    await db.InsertAsync(order, ct);
    await db.BulkInsertAsync(order.Items, ct);
    await db.ExecuteAsync($"UPDATE inventory SET stock = stock - {order.Items.Count} WHERE product_id = {productId}", ct);
});
```

### 3.2 整事务重试

按方言错误码重放（PG 40001/40P01、MySQL 1213/1205、SQLite BUSY/LOCKED），回调须幂等（at-least-once）：

```csharp
await db.WithTransactionRetry(async ct => await db.BulkInsertAsync(items, ct: ct));
```

### 3.3 保存点、外部事务与隔离级别

```csharp
// 长事务内部分回滚
await using var tran = await db.BeginTransactionAsync();
await db.InsertAsync(order);
await db.SavepointAsync(tran, "sp1");
await db.RollbackToAsync(tran, "sp1");
await tran.CommitAsync();

db.UseTransaction(externalTran);                      // 外部事务接入
db.WithIsolationLevel(IsolationLevel.ReadCommitted);  // 会话级，后续事务默认取用
```

### 3.4 弹性覆盖范围

只读自动，写入直连（非幂等写自动重试有重复执行风险）：

| 路径 | 覆盖 | 说明 |
| --- |:---:| --- |
| `From<T>()` SELECT 族、`GetAsync` / `GetAllAsync`、聚合 | 自动 | 瞬时故障按配置重试并计入熔断 |
| 连接建立 | 自动 | `CreateAsync` 自有重试循环 |
| 写入路径（Insert / Update / Delete / Save / Bulk / 存储过程） | 直连 | 需要弹性用 `ExecuteWithResilience` 显式包裹 |
| 事务内查询 / `ToPageAsync` / 原始 SQL 家族 | 直连 | 事务内重试会以次生异常掩盖根因 |

```csharp
// 非幂等写要弹性时显式声明（自行评估重复执行风险）
long affected = await db.ExecuteWithResilience(
    token => db.From<Order>()
        .Set(o => o.Status, OrderStatus.Paid)
        .Where($"id = {orderId}")
        .ExecuteNonQueryAsync(token), ct);
```

### 3.5 PG 咨询锁

必须在事务内，事务结束自动释放：

```csharp
await db.WithTransaction(async ct =>
{
    await db.AcquireXactLockAsync(resourceKey, ct);   // TryAcquireXactLockAsync 为非阻塞变体
    // 临界区...
});
```

## 4. 原生 SQL 与 SQL 资产

```csharp
var count = await db.ScalarAsync<long>($"SELECT COUNT(*) FROM users WHERE email LIKE {"%@example.com%"}");
```

SQL 文件在编译期嵌入并校验，可只取某个方言段：

```csharp
public static partial class Reports
{
    [SqlFile("Reports/MonthlySales.sql")]
    public static partial string MonthlySales();

    // Provider = "pg" 只提取文件内 -- @pg 方言段
    [SqlFile("Reports/Sales.sql", Provider = "pg")]
    public static partial string SalesPg();
}
```

`[SqlTemplate]` 把插值串提升为模板常量，免去每次字符串构造：

```csharp
public static class UserQueries
{
    [SqlTemplate("ActiveUsers")]
    public static FormattableString ActiveUsers()
        => $"SELECT * FROM users WHERE active = 1 AND deleted_at IS NULL";
}

var users = await db.QueryAsync<User>(UserQueries.ActiveUsers());
```

PG 专有：`WhereJson`（JSONB 路径查询）、`PgNotificationListener`（NOTIFY/LISTEN 异步监听，自动重连）、`NotifyAsync`（参数化 `pg_notify()`）。

## 5. 存储过程与错误处理

```csharp
// 强类型输入/输出参数，过程名白名单校验
var sp = db.StoredProc("sp_transfer_stock")
    .WithParam("from_sku", fromSku)
    .WithParam("qty", qty)
    .WithOutputParam<int>("rows_affected");
int affected = await sp.ExecuteAsync(ct);
int? moved = sp.GetOutputValue<int>("rows_affected");

// 唯一键冲突跨方言统一翻译，不用记各驱动错误码
try { await db.InsertAsync(user); }
catch (UniqueConstraintViolationException) { /* 邮箱已注册 */ }

// 乐观锁冲突
try { await db.UpdateAsync(order); }
catch (ConcurrencyConflictException) { /* 重新读取合并 */ }

// 健康检查：SELECT 1 探活，错误消息只透出异常类型名（防拓扑泄露）
HealthResult health = await db.HealthCheckAsync();
```

需要驱动原生能力时 `db.GetRawConnection()` 返回底层 `DbConnection`。

## 6. 横切关注点

```csharp
var db = await DataSession<PostgreSqlProvider>.CreateAsync(new DbOptions
{
    ConnectionString = connectionString,
    Interceptors = [new AuditInterceptor(loggerFactory.CreateLogger("Audit"))],
    SessionSetupSql = "SET TIME ZONE 'UTC'; SET search_path TO 'app, public'"
});
```

> ⚠️ `AuditInterceptor` 只覆盖实体 SELECT 管线、QueryBuilder UPDATE 与 `ExecuteAsync`；`InsertAsync` / `DeleteAsync` / `SaveAsync` / Bulk 家族 / 存储过程 / 迁移**不产生审计记录**。完整写入审计请用数据库层审计或 OpenTelemetry。

其余注解：`[SoftDelete]` 自动 WHERE 过滤、`[TenantAware]` + `WithTenant(id)` 列隔离、`[ConcurrencyCheck]` 乐观锁、`ForRead` 读写分离。23 个注解全表见 [API 参考](API参考.md)。

## 8. 批量 API 选型

| 场景 | 用 | 不用 | 理由 |
| --- | --- | --- | --- |
| 批量插入，不需要 ID 回填 | `BulkInsertAsync` | 逐条 / `SessionBatch` | 方言最快路径（COPY / LOAD DATA / 行预编译），一条往返替代 N 条 |
| 批量插入且需逐行回填自增 ID | `BulkMergeAsync`（默认键走逐条）或 `SessionBatch` | `BulkInsertAsync` | COPY / LOAD DATA 不回填 ID |
| 混合语句或需逐条语义控制 | `SessionBatch` | 逐条往返 | PG / MySQL 走 `DbBatch` 真单往返；SQLite 无批量 API，无参语句合并为单条多语句命令，其余顺序执行并复用命令 |
| 按非主键列批量更新（每行不同值） | `BulkUpdateBatchAsync` | 逐条 | 单语句多行 SET（PG `FROM VALUES` / MySQL `JOIN VALUES ROW`） |
| 乐观锁实体批量更新 | `BulkUpdateAsync` | `BulkUpdateBatchAsync` | 版本化单语句逐行校验版本；能力不全回退 DbBatch |
| 插入或更新（键存在则更新） | `BulkMergeAsync` | 手写 ON CONFLICT | 租户实体自动限定本租户（跨租户命中 0 行） |
| 大键集删除（万级以上） | `BulkDeleteAsync` | 逐条 Delete | SQLite json_each / PG = ANY / MySQL IN 分批，整批单事务，参数对象批间复用 |

## 9. 按形态选入口

同一个 API 在不同形态下开销构成不同，选对入口比库内微优化更值。

| 场景 | 入口 | 收益 |
| --- | --- | --- |
| 一请求一会话（Web / API） | `DataSessionPool.RentAsync` | 复用槽跨租约激活；租还约 1 µs |
| 高吞吐逐行写 | `BulkInsertAsync` / `BulkUpdateBatchAsync` | 会话与命令成本摊到 1/N |
| 大结果集 / 无界流 | `QueryAsyncEnumerable<T>` | 恒定内存，每行分配更低 |
| 单键查询 | `GetAsync` | 直查槽 + 单行物化 |
| 分页 | `ToPageAsync` | 单往返（PG 把 COUNT 与页 SELECT 打包） |

```csharp
// 启动时创建一次（maxIdleSize 默认 16，按峰值并发调整）
var pool = DataSessionPool<PostgreSqlProvider>.Create(options, maxIdleSize: 16);

// 每请求：租出即用，DisposeAsync 即归还
await using var db = await pool.RentAsync();
var user = await db.GetAsync<User>(id);
```

归还时瞬态状态（`With*` 覆写、拦截器加项）全部复位；租出时对脏会话复位连接级会话态（PG `RESET ALL; RESET ROLE` / MySQL `COM_RESET_CONNECTION`）并重放 `SessionSetupSql`；空闲超过 `PoolConnectionValidationInterval`（默认 30s）的会话先探活。命令复用槽、读连接、物化容量跨租期保留，**复用槽不经池化永不激活**（同形状第 3 次操作才晋升）。32 并发实测：P99 −18%、Gen0 −58%、每操作分配 −2576 B。

DI 容器把 `IDataSessionFactory<TProvider>` 注册为单例即可，不需要额外容器包：

```csharp
var factory = new DataSessionFactory<PostgreSqlProvider>(options, maxIdleSize: 16);
services.AddSingleton<IDataSessionFactory<PostgreSqlProvider>>(factory);

// 每请求（scoped 服务的构造或方法内）
await using var db = await factory.RentAsync(ct);
```

**逐条循环里每行开销由形态决定，不是可挤的库内水分**；高吞吐逐行写请换批量 API。

## 10. 边界与陷阱

- `WhereIn` 总绑定参数受方言上限约束（SQLite 999 / 通用 65535），超限提前抛 `ArgumentException`；更大键集用临时表 JOIN。
- `[ConcurrencyCheck]` 实体不要调 `BulkUpdateBatchAsync`：显式单语句 API 不承载逐行版本谓词（PALORM031 编译期即拦）。
- `BulkInsertAsync` 不回填自增 ID（COPY / LOAD DATA 契约）；需逐行回填用 `BulkMergeAsync`（默认键走逐条）或 `SessionBatch`。
- 事务内批量优先 `BulkInsertAsync` 而非 `SessionBatch`（前者走方言专用批量路径，后者是通用语句打包）。
- 可能存 NULL 的列声明可空属性（`string?`），非可空遇 NULL 会响亮抛 `SqlNullValueException`。
- `[TenantAware]` 实体会话创建后立即 `WithTenant(id)`，不要延后到首个查询（缓存 key 前缀随租户切换失效）。
- `InsertAsync` / `BulkInsertAsync` / `BulkMergeAsync` 不附加租户谓词，`tenant_id` 必须由调用方赋值（PALORM040 只拦可空列）；租户列在 Update / BulkUpdate 与 UPSERT 冲突更新中不可写（防跨租户搬移），确需迁移用原生 SQL。
- 需要跨租户管理查询时用 `IgnoreFilters()`；该调用把会话切到全量视图且**当前无公开复位 API**，管理查询结束请换一个会话（池化会话归还后重租即可）。
- 不支持嵌套事务（重复 `BeginTransactionAsync` 响亮抛异常）；长事务内部分回滚用 `SavepointAsync` / `RollbackToAsync`。
- 外部事务经 `UseTransaction` 接入后，外部已 Dispose 再用本会话会响亮失败（不静默自动提交）。
- 非幂等写不自动重试（写入路径直连语义）；确需弹性用 `ExecuteWithResilience` 包裹并自行评估重复执行风险。
- 敏感列标 `[SensitiveData]`：`Set()` 写入该列的参数值在审计日志中掩码；Where 手写 SQL 的洞值无列映射，不掩码。
- `AuditInterceptor` 覆盖面 = 实体 SELECT 管线 / QueryBuilder UPDATE / `ExecuteAsync`；写族与存储过程不产生审计记录。
- `[OwnedJson]` 对象形态必须配 System.Text.Json 源生成 `JsonSerializerContext`（AOT 硬要求，缺失编译期报 PALORM008-010）。
- `ToPageAsync` 的 `Skip()` 被忽略、`Take()` 被 `pageSize` 覆写，COUNT SQL 不经拦截器。
- 热路径的 `OrderBy` / `Select` 表达式提到静态字段（每棵树 512 B + 0.5~1.6 µs 的调用点成本可消除）。
- 超时异常带 `PalORM.InfrastructureTimeout` 标记的属基础设施侧（网络 / 服务器），先查环境再查代码；瞬时故障判定用 `Data["PalORM.IsTransient"]` 标记。
- PG 连接串 `NoResetOnClose=true` 下 raw SQL 的 `SET` / 临时表跨池租客可见（ITM-652）：需要隔离时用独立连接（`Max Pool Size=1`）或显式 `DISCARD`。

## 11. 部署清单

- 生产用 `DbOptions.Production`（已含弹性与连接池预设），只覆盖确需自定义的项。
- 一请求一会话部署：自建 `DbOptions` 时显式设 `CircuitBreakerScope.Process`，Session 级计数随会话销毁、短会话下阈值几乎不可能达到。
- 启动期预热连接池 `PreWarmAsync`（远程建连实测约 8.5 ms/条），配合 `MinPoolSize` 保持暖态。
- 只读副本配置 `ReadConnectionString` 后，报表 / 列表查询显式 `.ForRead()`，主从延迟敏感的强读留在主库。
- 高吞吐服务端开 `<ServerGarbageCollection>true</ServerGarbageCollection>`；容器配 `GarbageCollectionHeapHardLimit` 防 OOM。
- 只部署单方言时可设 MSBuild 属性 `PalORMTargetDialects` 裁剪 CRUD SQL 发射面（DDL 恒全方言）。
- 健康检查端点接 `HealthCheckAsync`；可观测性接 `WithTracing` + `WithMetrics`。
- MySQL 批量写报 `ER_NET_PACKET_TOO_LARGE` 先查服务端 `max_allowed_packet`；LOAD DATA 回退多值 INSERT 是 `local_infile` 关闭时的预期行为（非错误）。
