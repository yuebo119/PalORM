## 一、结论

六轮论证的净结果：**外部可移植内容为零**。Dapper 与 RepoDB 的每一项测试机制，PalORM 都已有等价物或已由更强的形态覆盖。真正的缺口在自有机制的两处空白：

| 缺口 | 事实 | 处置 | 成本 |
|---|---|---|---|
| 判据有效性证据 | Stryker 每周跑但**全部变异是 Ignored 或 CompileError**（3782 个变异点里 3160 + 622，零 Killed 与 Survived），手工回放只有 4 条且只覆盖 3 个缺陷族 | 补齐 D1 至 D7 的历史缺陷回放（7 条，其中 D7 已验证），建立"随修随加"纪律 | 2 小时 |
| 语句类型无组织 | 14 个语句类型与 12 个查询子句共 26 个坐标没有清单，新增类型时无人察觉缺断言 | 坐标登记表 + 反向守卫 | 0.5 小时 |

范围外另有一项值得裁决：工具链前滚（见第六节）。

前五轮曾把"手工变异规则扩到 14 条"作为主方案，第六轮推翻：Stryker 已在做全量变异，手工规则应只覆盖它覆盖不到的地方，而"覆盖不到的地方"第一优先级是修 Stryker 本身，不是另建一套。修不了时的退路是历史缺陷回放，不是抽象规则集。

## 四、真实缺口

### 4.1 判据有效性证据缺失（核心）

项目配有 Stryker，每周六 03:00 UTC 跑，覆盖 Core 的 20 个源文件与 SourceGen 全量，阈值 `{high: 80, low: 60, break: 40}`。但历史 report 显示：

| 状态 | 数量 | 含义 |
|---|---|---|
| Ignored | 3160 | 未评估 |
| CompileError | 622 | 编译失败，未评估 |
| Killed | 0 | 无 |
| Survived | 0 | 无 |
| 合计变异点 | 3782 | 有效信号为零 |

根因：`test-runner: mtp`，而 CI 注释记录的上游缺陷（stryker MTP 预览 runner #3799 同族，修复 PR #3817 已合未发版）导致变异无法执行。CI 对此的处理是 `exit 3/4 记 notice 不判红`，避免"狼来了"。

结果是：**四层防线的判据有效性目前没有任何自动证据**，只有手工的 4 条历史缺陷回放（R1a 软删过滤、R1b 第二注入路径、R2 RowFactory 列序、R4 AND 补括号），覆盖 3 个缺陷族，而报告声明覆盖 18 类。

### 4.2 历史缺陷回放未跟上修复节奏

D1 至 D7 修复了七条产品缺陷，回放规则只增加了 D7 一条（本次会话实测：注入 `RequiresElapsedCheck` 改 `=> false` → `ErrorContractTests` 3 项红、PG/SQLite 5 项绿，还原后 8 项全绿）。D1 至 D6 的修复没有对应的回放证据。

### 4.3 语句类型无组织

14 个语句类型与 12 个查询子句共 26 个坐标，没有清单，也没有反向守卫。新增语句类型时，是否有人给它写断言只能靠自觉。

## 五、方案

### 5.1 补齐 D1 至 D7 的历史缺陷回放（7 条）

沿用 `scripts/conformance-mutation-replay.cs` 的四步协议（注入、构建、期望报红、`git checkout` 还原、再构建、期望转绿）。每条规则对应一个真实发生过的缺陷。

| 编号 | 缺陷 | 注入点 | 目标过滤器 | 方言 |
|---|---|---|---|---|
| R-D7 | 超时未归一 | `CommandTimeoutNormalizer.RequiresElapsedCheck` 改 `=> false;` | `ErrorContractTests` | MySQL（**已实测**） |
| R-D1 | PG 时间列用 timestamp | `MigrationEmitter.cs:270` 与 `:278` 的 `"TIMESTAMPTZ"` 改 `"TIMESTAMP"` | `TimeKindMatrixTests` | PG |
| R-D2 | 批量插入不回填主键 | `DataSession_Bulk` 的 `BulkInsertReturningAsync` 改为委托 `BulkInsertAsync`（不回填） | `BulkInsertReturningTests` | SQLite 或 PG |
| R-D3 | SQLite 行锁放行 | `QueryBuilder.ThrowIfRowLockUnsupported` 的 `if (_dialect != SqlDialect.Sqlite) return;` 改为 `return;` | `BoundaryContractTests` 或 `QueryTests` | SQLite |
| R-D4 | 超时不解包 | `CommandTimeoutNormalizer.RunAsync` 的内层 `TimeoutException` 解包 catch 删除 | `ErrorContractTests` | PG |
| R-D5 | `SaveAsync` 无编译期拒绝 | `PalORMAnalyzer.CheckSaveWithConcurrencyToken` 改为空实现 | `AnalyzerDiagnosticsTests` | 编译期，无库 |
| R-D6 | `ToPageAsync` 放行 Skip | `QueryBuilderExtensions` 里 `if (paged._skip.HasValue) throw ...` 删除 | `ContractCatalog` 的 C-PAGE-01 | SQLite |

每条规则三要素：注入点可一行替换、可观测性（哪个期望值会变）、目标过滤器。R-D2 的注入面略大（委托替换），实施时按 `BulkInsertReturningAsync` 的实际实现定位。

### 5.2 "随修随加"纪律

把回放规则从"一次性补齐"改成"随缺陷修复自然增长"：以后每修一个产品缺陷，同一次提交里加一条对应的回放规则。理由：

| 维度 | 一次性写抽象规则集 | 随修随加 |
|---|---|---|
| 依据 | 假想的缺陷 | 真实发生过的缺陷 |
| 成本 | 集中 2 到 3 天 | 每次 0.3 小时 |
| 覆盖增长 | 停在写时的数量 | 与实际缺陷同步 |
| 验证成本 | 每条要设计可观测性 | 缺陷已有复现路径，可观测性天然存在 |

落地方式：写入 `docs/一致性测试总报告-2026-10-29.md` 的"未完成项"节，并在提交信息里标注（`Replay-Rule: R-Dx` trailer）。

### 5.3 语句类型覆盖守卫（0.5 小时）

借 `ArchitectureInvariantTests._filteredEntryPoints` 的现成形态，做一份坐标清单。

```
test/PalORM.Core.Tests/StatementTypeCoverageTests.cs
    映射表：坐标 → 覆盖它的测试文件
    断言 1：每个坐标的覆盖文件存在且含至少一处 SQL 断言
    断言 2：产品侧出现新坐标而未登记时失败
```

坐标来源：

| 轴 | 数量 | 枚举方式 |
|---|---|---|
| 语句类型 | 14 | 手写清单，从 `MigrationEmitter`、`CommandFactoryEmitter`、`DataSession_Bulk`、三 Provider 的 SQL 常量归纳 |
| 查询子句 | 12 | `QueryClauseKind` 反射枚举（Comment、CommonTableExpression、DefaultFilter、GroupBy、Having、Join、Lock、OrderBy、Raw、Set、Where、Window） |

它挡的是"新增语句或子句但无人写断言"。不评估断言质量，质量由 Stryker（修复后）与回放规则承担，三者不可互相替代。

### 5.4 UPSERT 三方言形态断言（0.5 小时）

PG `ON CONFLICT`、MySQL `ON DUPLICATE KEY UPDATE`、SQLite `ON CONFLICT DO UPDATE` 各 1 条片段断言。现状仅 `BulkBatchCapacityTests` 一处 `Contains("ON CONFLICT")`。
