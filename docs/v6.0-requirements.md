# PalORM v6.0 需求定稿

> 状态：**已定稿**（2026-09-28，用户逐项裁决闭环）· 基线：v5.9.0（ee15a64）
> 来源：四轮代码挖掘（2026-09-27/28）+ 辩证论证 + 用户裁决。本文件是 v6.0 需求的唯一真源；
> 技术方案见 `docs/v6.0-master-plan.md`，任务分解见 `docs/v6.0-tasks.md`。

## 一、版本背景

- 性能线已收官：5.8.0 自报"已识别未处置性能点为零"，v6.0 无性能欠账。
- 外部需求为零：GitHub issue/PR 全为维护者流程件，无社区 feature request——v6.0 为内部驱动。
- 5.x 期间四条"自陈未完成"债务到期：IRowFactory（ADR-H）、DiffAsync（PALORM901）、
  `[DefaultValue]`（ITM-580 / ADR-B B1 分期）、`[Column]` 架构参数（ADR-B B1 分期）。
- v6.0 是 SemVer major 窗口，破坏性变更的合法执行时机。

## 三、逐项需求

### R1：DTO 投影物化

**问题**：RowFactory 只为 `[Table]` 实体生成；`QueryAsync<T>`/`GridReader` 要求类型已注册。
join/报表结果映射到非表类型无干净路径——唯一 workaround 是 `[Table]` 假实体，而它会被
`MigrateAsync` 建成真表（数据字典污染陷阱）。

**需求**：新注解 `[Projection]` 标记只读物化类型；源生成器为其生成 RowFactory（ordinal 映射，
ADR-A 契约）并注册；`QueryAsync`/`QueryFirstAsync`/`GridReader`/`StoredProcBuilder.QueryAsync`
自动受益。不生成 CommandFactory、不参与迁移 DDL、不参与租户/软删过滤（投影无表）。

**边界**：只做物化映射；不做 LINQ 投影表达式、不支持 `From<Projection>()` 链式（无表可查）。

### R2：`[DefaultValue]` DDL 落地

**问题**：注解已公共暴露（ITM-580 自陈未实现），表达式不参与 DDL 生成，标注即触发
PALORM017 编译期告警；用户被迫用 `[SqlFile]` 或建表后 ALTER，schema 声明分裂为两套真源。

**需求**：MigrationEmitter 在列定义追加 `DEFAULT {表达式}`，表达式原样进三方言 DDL
（与 `[Computed]` ITM-541 同契约：不经转义、不做方言翻译、合法性由调用方负责）；
PALORM017 对 `[DefaultValue]` 停报。

**边界**：DDL-only。插入路径行为不变（属性值照写，DEFAULT 仅在 DDL 层对未显式插入的
场景兜底）；不做"属性未设置时跳过列"的智能推断。

### R3：`[Column]` 类型细化

**问题**：Length/Precision/Scale/TypeName 命名参数触发 PALORM017（不参与 DDL）；字符串列
DDL 全走方言默认宽度，实体声明的 `VARCHAR(50)` 契约不落地。后果：MySQL TEXT 列不能直接
建索引（需前缀）、PG 无宽度约束、列宽契约对 ORM 不可见。

**需求**：TableModel 解析四个参数；MigrationEmitter 按方言生成类型细化
（PG `VARCHAR(n)`/`NUMERIC(p,s)`；MySQL `VARCHAR(n)`；SQLite 类型亲和性下长度为声明性
不强制，原样写入）；TypeName 直通最高优先。PALORM017 对 Column 架构参数停报。

**闸门**：Length/Precision 先行；TypeName 视中途进度决定进本版或拆出。

### R4：跨方言唯一冲突异常

**问题**：捕获唯一约束冲突必须写三方言 catch 分支（`PostgresException.SqlState == "23505"` /
`MySqlException` 1062 / `SqliteException` 19）——与 PalORM"跨方言抽象"的核心卖点不对称。

**需求**：`UniqueConstraintViolationException : PalORMException`；`IDbProvider` 增加
`static virtual bool IsUniqueViolation(Exception)`（默认 false，三 Provider 各自覆写）；
写路径命中判定时包装抛出，`InnerException` 保留原生异常（纯翻译不吞）。

**边界**：只统一类型不抽象约束名（PG 的 ConstraintName / MySQL 的 key 名字段形态各异）；
Upsert/Bulk 家族自身的冲突处理语义不受影响；唯一冲突不参与重试（维持现状）。

### R5：`WithMetrics(name)` 转正

**问题**：name 参数经非空与非法字符校验后丢弃（XML doc 明说"仅保留 API 兼容"）；
metrics tag 只有 operation/provider/outcome 三维，无业务名维度。

**需求**：name 透传为 metrics tag（如 `palorm.query.name`），未设置时不加 tag
（无 metrics 名场景的时间序列基数不变）；XML doc 载明低基数警示（name 应为静态业务名，
禁止拼接动态值）。ADR-M"若补 label 支持则保留"条款命中。

### R6：删除四项公共 API（破坏性变更）

| 成员 | 依据 | 现状证据 |
|------|------|---------|
| `IRowFactory<T>` 接口 | ADR-H（2026-08-15 裁决） | v5.2 起 `[Obsolete(PALORM900)]`，零实现零消费 |
| `DataSession.DiffAsync<T>` | v4.0 起 `[Obsolete(PALORM901)]` | ValidateSchemaAsync 的薄包装，无新信息 |
| `DbOptions.NamingConvention`（属性 + `ApplyNaming` + 枚举） | ADR-M | 设置后静默无效——生成器编译期按注解映射，运行时选项零消费方 |
| `DbOptions.PoolExplicitlyConfigured` | ADR-M | 零读方死字段（仅 WithPool 置位；SqliteProvider 历史消费方已移除） |

NamingConvention 为未预警破坏（从未标过 Obsolete），**迁移指南必须显式列出并说明**
（删除该设置即可，行为从未生效过）。

### R7：ADR-M 重写 + 发布配套

ADR-M 重写（窗口号"3.0"系笔误，实际窗口即 v6.0；三项处置：删/删/转正 + 证据行号刷新）；
破坏性变更 ADR；README 迁移指南；CHANGELOG 未发布段建立；v5.x LTS 决策（建议不建 LTS，
5.9.0 为 5.x 终版——零外部用户，无维护承诺负担）。

### G：向量搜索 Phase 1 PoC（门控并行）

按 `docs/v6.0-vector-search-design.md` 执行 Phase 1，**动工前先刷新设计文档的过时假设**
（2026-07-28 草案：sqlite-vec 已发 0.1.9；文中引用的 7 月行号需重核）。

**决策门**：PoC 验证 `Npgsql UseVector()` AOT 发布 0 警告 + API 可用 → 全量进 v6.0
（追加 8-11 天）；证伪 → Raw 手写配方文档化，v6.0 照发不受损。

## 四、明确不做项

| 项 | 理由 | 去向 |
|----|------|------|
| 写联动查询缓存失效 | TTL 有兜底（最终一致是文档化定位）；key 反解涉及 ADR-C 全局状态 | v6.1 候选 + 独立 ADR |
| `[ForeignKey]` 约束 DDL | ADR-B 显式挂起：SQLite FK 内联 = 建表逻辑内核重构 + 增量迁移未决 | 迁移系统整体设计立项时一并做 |
| 表达式树谓词 `Where(x => ...)` | 与 FormattableString 显式 SQL 哲学冲突；参照系偏置（B28） | 不做 |
| 迁移版本化/回滚 | 声明式幂等哲学自洽（schema 真源是实体注解） | 不做 |
| NamingConvention 转正（csproj 属性驱动） | 与显式注解哲学冲突 + YAGNI（零用户反馈） | 留待真实请求重开 |
| 复合主键 / StoredProc TVP / Metrics 维度扩展 | P3 级或 micro-ORM 定位外 | 不进 v6.0 |
