## 3. 异常判读（门禁 0 项 FAIL）

门禁本身零失败；以下五项是需要人工过目的判读项。核心判据层级（B100）：分配 > 绝对耗时 > 同轮比值 > 跨轮比值。

### A. 并发 t4/t8 比值被高估（工具缺陷，已修复）

🩺 **症状**：首轮报告的关键项速览显示 MySQL `Concurrent_Mixed80_20 (t8)` 比值 **1.73**、t4 **1.12**；原始台账同批为 ADO t8 313.3 ms / PalORM 329.7 ms = **1.05**，t4 206.5 / 213.5 = **1.03**。上一批同样现象（显示 1.90，实际 1.04）。

🔍 **根因**：`bench/PalORM.PerfHub/Program.cs` 的地板查找按 `方言 + 操作 + 行数` 匹配，漏了 `ConcurrencyThreads`，`results.Find` 取到首个匹配即 t1 行，于是 t4/t8 全部除以 t1 地板。老信封里 ADO 组（自己除以自己）的比值分别是 MySQL t8 **1.64**、t4 **1.08**，直接暴露了错位。

⚖️ **影响面**：每批 3 方言 × 2 档 = 6 行展示值失真。结果库把这些行标为不可比（`Incomparable`，门禁按设计跳过 20 项），所以**不影响门禁判定**，只影响报告展示。

👉 **修复**：地板匹配追加 `&& b.ConcurrencyThreads == m.ConcurrencyThreads`；同时新增写入期自检——ADO 组比值必须恒为 1，任何偏离立即抛错，宁可本批失败也不产出错比值信封（老信封里该自检会命中 5–6 项，新批 0 项）。

✅ **验证**：13:03 复跑批 416 项，自检通过（ADO 比值异常 0 项），并发比值回到实际水平：

| 方言 | t1 | t4 | t8 |
|---|---:|---:|---:|
| SQLite | 1.00 | 1.02 | 1.00 |
| MySQL | 1.04 | 1.03 | 0.99 |
| PostgreSQL | 1.02 | 1.01 | 1.01 |

结果库门禁复跑：比对 171 项、失败 0、非可比跳过 20，与修复前一致。索引基线无需重录（这批行本就不进门禁），下次常规录制会自动带上正确比值。

### B. 快于地板 >33% 的项（地板健全性待核）

🩺 **症状**：PG BulkDelete 2000 **0.67** / 20000 **0.42**，PG UpsertBatch 2000 **0.58** / 20000 **0.63**；另有 MySQL TxRollback 0.61、IncludeJoin 0.62（后两项不在四组表）。

🔍 **证据**：①形态差异有源码依据——PG 删除走 `= ANY(@ids)` 数组参数，ADO 地板走 IN 占位符；PG upsert 同为数组形态。②跨批稳定：2026-10-30 批 BulkDelete PG/20000 即 0.42，本轮复跑仍 0.42。③地板组自身健康：复跑批 HealthRatio 0.081（阈值 0.35），地板未漂移。

⚖️ **判定**：不是地板实现缺陷，而是"产品形态优于基准组写法"；比值照常展示，但结论应表述为"批量族快于手写 SQL"，不当作异常。MySQL TxRollback / IncludeJoin 机制本轮未核查，仅登记为既有稳定值，不作归因。

👉 **处置**：无动作；若将来把 ADO 地板改成同形态数组参数，这些比值应回落到 ~1.0，届时应同步改基线。

### C. PG WideQueryAll/2000 单批高位（已复测回落）

🩺 **症状**：首轮 PalORM 1.68 → **2.12 ms**（+26%），同批 ADO 1.71 → 2.00 ms（+17%），Dapper 1.68 → 1.73 ms（+3%）；比值 0.98 → 1.06。

⚖️ **判定**：13:03 复跑落到 **1.69 ms、比值 0.97**，回到历史区间。单批尖峰成立，不判回归。

👉 **处置**：闭环，无需后续动作。

👉 **处置**：闭环，无需后续动作。

### E. SQLite BuildComplexQuerySql 的单组抬升（已复测回落）

🩺 **症状**：首轮 PalORM 2.50 → 4.30 µs（1.72 倍），ADO/Dapper 保持 0.40/0.20 µs。

## 6. 指标定义与判读纪律（附录）

- **时延**：`MedianNs`（全路径中位数），冷热同批；P/ADO = PalORM ÷ ADO.NET − 1（正 = 慢 = 劣）；P/Dapper 以 Dapper 为基准。
- **分配**：`AllocatedBytesPerOp`（确定性指标，不受调度影响），色标与阈值同为 -30% / -10% / -1% / 0 / +1% / +10% / +30% 六级。
- **预算**：P/ADO ≤ 1.30 为门禁线；≥1.50 或 ≤0.67 加 📌 待判读（两个方向都过目）；地板健全性要求任一 ORM 实现不得快过 ADO 超过 10%——超出时先查形态差异再下结论。
- **判据层级**：分配 > 绝对耗时 > 同轮比值 > 跨轮比值；地板自身漂移 >18% 则该轮相关项作废。
- **共移核对**：某一项变慢时先看三组是否同向；三组同向 = 环境态，单组独走才立案。
- **未复测不归因**：单批观察只能登记为"待确认"，不得写成结论。
- **可比性**：跨机绝对值不可比；同批比值、分配、往返数可比。P95/P99 只展示不门禁。
