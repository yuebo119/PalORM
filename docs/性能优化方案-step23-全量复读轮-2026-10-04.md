## 一、N6：T6 租户作用域缓存命中路径的 ToString 漏项（落地）

**发现**：`TenantScopeCached` 的命中判定 `tenantId as string ?? tenantId.ToString()`——
T6 消掉了 Scope 拼接（~32B/查询），但比较路径对非 string 租户（装箱 int/long/Guid）每次
`From<T>()` 仍 `ToString()` 一个新串。T6 注释声称"命中零拼接"，实际只对 string 租户成立
（承诺与实现不对称——step22 N1 的同族判据）。

**修法**：`TenantScopeEntry` 存装箱原值（object），命中走 `TenantValueEquals`：
ReferenceEquals 快路径（同会话同一箱，命中即返回）→ string 走 Ordinal 分支（与旧形态
逐位一致）→ 其余走装箱值 `Equals`（解箱值比较，零分配）。
语义等价性：int/long/Guid 的值比较与 ToString 形态比较同判定（这些类型的 ToString 对值
单射）；Guid 租户收益更大（32 字符 ≈ 80B/查询）。

**量化（TenantScopeDiag 探针，.ai/perf-probe tenantscope 命令，同会话背靠背 A/B，
多位数租户 42_000_000_123）**：

| 臂 | long 租户命中（B/查询） | string 租户（对照） |
|---|---|---|
| 旧码 | 351.5 | 303.4 |
| N6 | **302.3** | 311.6（同带摆动） |

**−49.2 B/查询**，long 租户收敛到 string 租户同带（租户路径不再因存储形态多付分配）。

**附带发现（.NET 运行时事实，实测）**：个位数（0-9）的装箱 `ToString()` 返回驻留缓存串
（0.00 B/call），多位数 39.99 B/call——个位数租户两形态都不分配，N6 对其为零面改动。

## 二、N7 证伪与勿重开（实施→测试咬人→回退）

原判断：UNNEST 数组路径三处（`ExecuteArrayFormDeleteAsync` 经 `BuildArrayParameter`、
两个数组形态执行器经 `CreateTypedArrayParameter`）每批每列新建一个**从不挂到命令**的
参数只为取 `.Value`，而 Npgsql 构造函数原样存储数组 → 判为纯废重，"终态逐位一致"。

**证伪证据**：实施后 Core 并行套件 **15 失败**（BulkUpdateArrayFormTests /
BulkDeleteArrayFormTests）——本地夹具 `ArrayFormDialectProvider` 的
`CreateTypedArrayParameter/CreateArrayParameter` 把数组**转形**为 JSON 文本（`ToJsonArray`），
由连接层重写 `json_each` 执行。即这两个 IDbProvider 公开成员是 **Provider 值塑造钩子**
（契约语义），"丢弃型参数"正是值塑造的载体；PG 的恒等实现只是特例。

**教训（B95 同族——读产物实现要读全）**：判断"Provider API 产物恒等"时只看了唯一生产
实现（Npgsql），漏了接口契约面与既有测试夹具。已整体回退；**勿重开**。
附带登记（仍然有效，低于线不动）：`PostgreSqlProvider.CreateArrayParameter` 对象初始化器
先设 `NpgsqlDbType = element` 再由下一行覆写 `Array | element`（双 setter）。
