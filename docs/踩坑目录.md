## 清洗说明

**去重**：同质坑合并。例："连接池耗尽"有 15 条表面症状→保留 1 条核心。

**去冲突**：
- "CASCADE DELETE 应默认开启" vs "应默认关闭"→保留"默认 NO ACTION，需显式 opt-in"（PostgreSQL 最佳实践 + 230 万行生产数据丢失教训）
- "ORM 应自动管理连接" vs "用户自己 Open/Close"→保留"using-scoped 自动管理"（Hibernate 创始人认错 Stateful Session）

**去除不适用 V8**：
- Stateful Session 相关（V8 不做）→标注"架构层面避开"
- Lazy Loading 相关（V8 不做）→同上
- Change Tracker 相关（V8 不做）→同上
- 继承映射 TPH/TPT/STI（V8 不支持）→同上

**去除不必要**：
- 文档/培训/社区相关（V8 未实现→无指导意义）
- 纯运维问题（DB 升级/备份策略→不是 ORM 职责）

| # | 场景·问题·后果 | 必要性 | V8 对应设计 | 验证逻辑 |

## Phase 23: PalORM 实战新增陷阱 (7 条)

> 以下为 PalORM 从设计到实现的完整周期中，实际踩到的坑。每条均已修复。

| # | 场景·问题·后果 | 根因 | 修复方案 | 状态 |
|---|------|------|------|:--:|
| 296 | **场景**: `struct QueryBuilder` 中 lambda 捕获 `this`。**问题**: C# 不允许 struct 内 lambda/匿名方法访问实例成员(`CS1673`)。`Select(m => _quoteIdentifier(...))` 编译失败。**后果**: struct 迁移时 38 个编译错误 | struct 的 this 是值类型，lambda 捕获是引用语义 | lambda 外提前捕获到局部变量：`var q = _quoteIdentifier; ...Select(m => q(...))` | ✅ 已修复 |
| 297 | **场景**: CRUD 统一到 `CrudMetadatas` 字典后，AOT 项目手写注册表未同步。**问题**: AOT 测试项目使用手动编写的 `.g.cs` 文件，不含 `CrudMetadatas` 初始化。升级后 `InsertAsync` NRE 崩溃。**后果**: AOT 原生二进制运行即崩 | 手写注册表与新字典结构不同步 | `InsertAsync/UpdateAsync` 添加 `CrudMetadatas is null` 回退→旧版分离字典 | ✅ 已修复 |
| 298 | **场景**: `Roslyn 5.10` 预览版无法加载 ProjectReference 源生成器。**问题**: SDK 自带 Roslyn 5.800，NuGet CodeAnalysis 5.10 装配版本不一致→`Initialize()` 静默失败。**后果**: 源生成器完全不产出代码，69/76 测试失败 | NuGet 5.1000 程序集版 vs 编译器 5.800 版类型不兼容 | 锁定 NuGet `Microsoft.CodeAnalysis.CSharp 5.6.0` 稳定版，等 SDK 11 RC 后升级 | ✅ 已规避 |
| 299 | **场景**: `RS1041` 强制源生成器目标 `netstandard2.0`。**问题**: `IncrementalGeneratorInitializationContext.AdditionalTexts` 仅在 net8.0+ 引用程序集中暴露→netstandard2.0 不可用。**后果**: SqlFile 源生成被阻断（后来用 `[SqlFile]` 特性替代了 AdditionalTexts） | Roslyn 双重锁定：RS1041 禁升 TFM + AdditionalTexts 仅在 net8.0 构建中 | 使用 `ForAttributeWithMetadataName("SqlFileAttribute")` 替代 `context.AdditionalTexts`——任何 Roslyn 版本通用 | ✅ 已规避 |
| 300 | **场景**: `where T : class, new()` 约束无法传播 `IRowFactory<T>` 接口。**问题**: 架构设计时计划 `where T : class, IRowFactory<T>, new()`，但源生成器生成的是独立 RowFactory 类，T 本身不实现该接口。**后果**: 泛型约束与实际类型系统不匹配，编译失败 | 源生成模式中 T 是实体类型，RowFactory 是生成的独立类型 | 改 `where T : class, new()` + 内部通过 `PalORM_Runtime.RowFactories[typeof(T)]` 获取工厂 | ✅ 已采纳 |
| 301 | **场景**: `WithFilter(Expression<Func<T,bool>>)` 在 AOT 下无法工作。**问题**: `Expression.Compile()` 依赖运行时动态代码生成→NativeAOT 不支持。**后果**: API 声称可用但 AOT 下崩溃 | Expression 编译 ≠ AOT 安全。与 FormattableString 路线不可调和 | 删除 `WithFilter(Expression)` API。全局过滤改用 `[SoftDelete]`/`[TenantAware]` + `Where(FormattableString)` | ✅ 已删除 |
| 302 | **场景**: DataSession 与 QueryBuilder 各自解析 FormattableString。**问题**: DataSession 只替换精确 `{n}`，`{0:N1}` 会原样进入 SQL；QueryBuilder 未完整拒绝非法复合格式。**后果**: Provider 语法错误或异常类型不确定 | 重复实现造成语义漂移 | 统一 formatter：先用 BCL 验证复合格式，再单次扫描映射参数名；alignment/format specifier 不格式化参数值 | ✅ 已修复 |
