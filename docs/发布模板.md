## [X.Y.Z] - YYYY-MM-DD

一句话概述（≤80 字，本版主体变化，会成为 Release 页首行；不分行）

### 💔 破坏性/行为变更

> 仅在存在签名破坏或行为变更时保留本段，否则整段删除。位置固定在头条之下。

- **短标题**：调用方要做什么 + 必要细节（Release 页只取第一句，第一句必须是迁移动作）

```csharp
// 旧版本写法
// 新版本写法
```

- **短标题**：旧行为 → 新行为，写清影响范围（方言、档位、默认值）

### 变更要点

- **新增**：一句话描述（新 API 写全签名）
- **修复**：一句话描述症状与修复方式，写清受影响版本区间
- **性能**：优化描述 + 实测数字与口径（方言/档位/批次），无实测写"机制改进，未基准"
- **依赖升级**：包名 旧版本 → 新版本
- **验证**：N 个测试全绿（Core N + SourceGen N + Integration N，含 PG/MySQL 真库）〔内部〕

---

## 填写要求（提交前逐条核对）

| 项 | 要求 |
|----|------|
| 版本标题 | `## [X.Y.Z] - YYYY-MM-DD`，日期等于 tag 提交日 |
| 头条 | 标题下第一段，≤80 字，写本版主体变化 |
| 条目形态 | 每条 `- **短标题**：细节`，短标题 2~32 字符 |
| 破坏性 | 签名破坏或行为变更必须有 `### 💔` 段，其余条目不得混入该段 |
| 内部条目 | 测试断言搬迁、基准工具、探针、门禁脚本写在要点里并加 `〔内部〕`，不进 Release 页 |
| 条目粒度 | 一句一个事实，禁止"修复了若干问题"式概括 |
| 数字 | 全部来自本次实测，禁止沿用上一版 |
| 格式校验 | `dotnet run --file scripts/pre-release-check.cs -- <新版本>` 必须全绿 |
| 预览 | `dotnet run --file scripts/release-notes.cs -- <新版本>` 查看 Release 页成品 |

格式细则见 [发布变更日志规范](发布变更日志规范.md)；版本号语义见 [发布规范](发布规范.md) §1.2。
