# 性能优化方案:微项包 R1(2026-10-13)

> 立项背景:二轮方案收口后,剩余可挖项全部在 1~3% 区间(低于 5% 时延不做线)。
> 用户裁决(2026-10-13):不降线;以**打包**方式合法捞回低于线的收益——多个 1~3% 项
> 一次落地,测**包的总和**,包总和过 5% 线才立项有效。
> 纪律:时延线维持 5% 不动;分配侧维持"精确字节可证即做"(等效 0 线,现状);

## 一、候选项清单(入包三项)

### A1 方言定型行工厂(P2-1 重开,包内主项)

- **内容**:RowFactoryEmitter 按 PalORMTargetDialects 发射定型读取器——
  NpgsqlDataReader / SqliteDataReader / MySqlDataReader 具体类型的物化器(消每列每行
  DbDataReader 虚分发;DateTimeOffset/TimeSpan/byte[]/TimeOnly 族从泛型
  GetFieldValue&lt;T&gt; 换驱动专用 getter,JIT 可内联)。注册表按方言携带定型工厂,
  From&lt;T&gt;/QueryAsync/GetByKey/GetAll 按方言选用;未定向/第三方方言回退现有
  DbDataReader 泛型工厂(行为零变化)。
- **预估**:宽行物化路径 2~4%(WideQueryAll/QueryAll/GetAllAsync/GetByKeySession 族);
  分配不变(纯时间侧)。
- **风险**:生成器 ×3 方言快照 churn;Registry 增 per-dialect 工厂面;AOT 需全链路验证
  (P0#3);P2-1 原关账分析为 1~3%(单态虚调用 + JIT 去虚化吃掉大半),**包内重开的前提
  是 PoC 实测 ≥2%**,否则从包中剔除。
- **前置 PoC**:不动生成器,手写一个 20 列实体的 NpgsqlDataReader 定型工厂,真库 PG
  interleaved A/B 对照泛型工厂,物化段(剔除网络)比值。PoC &lt;1% → A1 证伪出包。

### A2 GetAsync/DeleteAsync 泛型键重载(消调用点装箱)

- **内容**:现签名 GetAsync&lt;T&gt;(object key) 使 long 键在调用点装箱(24B/op);
  新增值类型键重载(如 GetAsync&lt;T&gt;(long key) / DeleteAsync&lt;T&gt;(long key),
  键进槽路径走 P1-4 identity 快路径零转换)。字符串键走既有 object 签名。
- **预估**:−24B/op 精确可断言(分配侧本就"精确可证即做",此项不需要打包即可做,
  入包是为让包总账更丰满);时延 ~0。
- **风险**:公共 API 面 +1(需过特性推荐四问:ORM 职责✓/AOT✓/调用方自己做不更好✓/
  真必需✓——高频单键读是 ORM 核心场景)。文档三方一致同步。

### A3 事务循环 owner 重入无锁快路径

- **内容**:Enter(owner) 在 ownedOperation 命中时仍取锁——WithTransaction/
  TxHundredInserts/TxRollback/EnumInserts 形态每行一次锁往返。增无锁快路径:
  Volatile 读 _isActive/_activeOperationOwner/_parallelReadScopes,owner 命中且无
  并行作用域时免锁返回 default 租约;Exit 对称(仅 owner 快路径命中时免锁)。
- **正确性论证义务(实施时必须写清)**:快路径漏读的竞态界——_isActive 只在锁内变,
  快路径读到 false 但实际刚变 true 的窗口,后果 = 本该重入的行被拒(响亮失败,非静默
  数据错);读到 true 但实际刚变 false = 保守回落锁路径。两个方向都不产生静默错误,
  这是可接受的竞态界,实施时以并发测试族锁定。
- **预估**:写循环族每行 ~20~40ns,约 2~4%(EnumInserts 1.77×/TxRollback 1.44× 的
  客户端残余主要成分之一)。
- **风险**:SessionOperationState 是全库最核心的并发原语,改动必须有并发测试族 +
  现有 590 全量回归背书。

## 二、不入包登记(维持关账)

形状哈希增量化(总工作量不变,已证伪)、CTS 复用(语义本体)、弹性包装 272B(语义)、
WhereIn 占位符批片优化(数组形态已覆盖 PG)、MySQL 批分页(快照一致性资产)、
窗口融合分页(RTT 红利已收)。

## 三、打包 A/B 判定方案

- **基准集(包总和的测量面)**:
  - 物化臂(A1 主收益):WideQueryAll / QueryAll / GetAllAsync / GetByKeySession,三方言
  - 写循环臂(A3 主收益):TxHundredInserts / TxRollback / EnumInserts,SQLite
  - 单键读臂(A2 精确字节):GetByKey,PG/SQLite
- **判定**:包落地前后**同批 interleaved A/B**(pre 包提交 vs post 包提交,同日同机),
  逐臂中位比值;**包总和过线判据 = 至少两个代表臂时延改善 ≥5%,或全部代表臂 ≥3% 且
  方向一致**;A2 的 −24B/op 以精确字节断言单独登记(不走时延判据)。
- **实施顺序**:
  1. A2 独立小刀先行(半天内,精确字节即刻兑现);
  2. A1 PoC(手写定型工厂,真库 A/B)——≥2% 才动生成器全量,<1% 出包;
  3. A3(并发原语改动,配并发测试族);
  4. 全包同批 A/B 收口,过线则按 PerfHub 全量批重录基线收尾;不过线则撤包或重估构成。
- **停止条件**:包总和 <5% 且无臂 ≥3% → 包证伪,登记 Rejected-Alternative 后收档;
  A1 PoC 证伪 → 重估剩余构成(A2+A3 单独不足 5% 时同样收档)。
