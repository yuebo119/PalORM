# PalORM 静态缓存清单（CACHE-010 · 2026-09-19）

> 审计 2026-09-19 A1 整改的配套治理：本清单登记 PalORM 进程级（跨会话共享）静态可变状态的**键空间、容量策略、淘汰策略**三要素。
> **维护规则**：新增任何 `static` 可变集合/缓存，必须同步登记本清单；无界设计必须给出"键空间有限"的论证，给不出则必须有容量上限（参照 `BoundedQueryCache` 的 1024 纪律）。Code Review 时以本清单为核对表。
> 相关：`SqlShapeCache` 的容量治理（审计 A1）与 `WithCache` 多租户警告（ADR-C、README 特性表）。

## 纪律依据

- **快照范本**（#1）：注册表热读零锁竞争，其余静态缓存新增时应参照。
- **1024 纪律**（#7/#8）：`BoundedQueryCache` 首创（容量满且无可淘汰时拒写，不做无界扩张）；`SqlShapeCache` 审计 A1 整改后对齐。
- **有限键集豁免**（#2-#6）：键全部由编译期实体集/代码字面量决定，运行时无法注入新键（`WithCache` 的 key 不属于此列——那进入的是 #7 的有界缓存）。**新增缓存若键含运行时值（用户输入/页码/时间），必须走 #7/#8 的有界模式或论证排除。**
- 历史教训：SqlShapeCache 初版（commit 97fdfb6）无界 + 键含 OFFSET 动态值，10,000 页分页即 10,000 永久条目——审计 A1 实测（`SqlShapeCacheGrowthTests`）。
