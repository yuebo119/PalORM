## 五之一、已确认产品缺陷（2026-10-29 复核）

首轮零失败之后，逐条追问"这些记录下来的行为是否合理"，发现三条应判为缺陷而非契约。其中第一条由探针实测确认，影响最大。

| 编号 | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| D1 | PostgreSQL 上 DateTime 列读回 Kind 丢失，导致"读出改回写"抛 `ArgumentException` | 根因是列用 `timestamp`（无时区）而参数用 `DbType.DateTime`（Npgsql 视为 timestamptz）。**已修复（2026-10-29）**：列类型改为 `timestamptz`，读回 Kind=Utc、刻度不变、往返可用；回归测试 `PostgreSql_DateTimeRoundTrip_ReadThenWriteBackSucceeds`；老库需手工 `ALTER COLUMN ... TYPE timestamptz` | P0（已修） |
| D2 | `BulkInsertAsync` 不回填自增主键，与同产品 `BulkMergeAsync`（PG/SQLite 多行 INSERT..RETURNING 按序回填）不一致 | 0b 阶段实测：首版批量测试三项静默失败（按 Id=0 更新影响 0 行），`BulkDelete` 一项假通过。用户按常规写法拿回 Id 会拿到 0 | P0 |
| D3 | `ForUpdate` / `ForShare` 在 SQLite 上构建期不拒绝、执行期由数据库报语法错 | 实测 `SqliteException: near "UPDATE": syntax error`；源码注释登记为 ITM-639，但登记不等于合理：正确形态是构建期按方言抛 `NotSupportedException` | P1 |

同族不一致（应改，但严重度低于上述三条）：

| 编号 | 现象 | 问题 |
|---|---|---|
| D4 | 命令超时抛 `NpgsqlException`（`Exception while reading from stream`），连接超时抛 `TimeoutException` | 同族异常类型不一致，`catch (TimeoutException)` 会漏掉命令超时 |
| D5 | `SaveAsync` 对并发令牌实体在运行期抛 `NotSupportedException`，`BulkUpdateBatchAsync` 在编译期由 PALORM031 拦下 | 同一约束两种拒绝时机，用户在不同 API 上反馈形式不同 |
| D6 | `ToPageAsync` 静默覆写用户已设的 `Skip()`、`Take()` | 静默丢弃显式设置属危险行为，应改抛异常或在 API 文档明示 |

### 判据设计的教训

D1 到 D3 在首轮全部"通过"，根因是判据把"当前行为"当成"合理行为"固化：时间矩阵的判据是"刻度相等 + Kind 等于该方言实测值"，它接受 Kind 丢失；批量测试改用显式主键形状绕开了回填问题；SQLite 的 `ForUpdate` 断言按实测写成"抛 SqliteException"。

这对应方案 §5.2 已经写下的纪律「契约期望值一律从文档取，测试只登记实际值并交由评审」。实现只做到了"登记实际值"，缺了"交由评审"这一步。评审要回答的问题恰好是"这个行为合理吗"，本轮补上之后三条缺陷才浮出。

## 六、残余风险声明（方案 §8.3 模板）

> 本次运行覆盖 18 类缺陷族，其中 15 类有直接判据（SQL 语法与引用符、参数序错位、列序与物化错位、DDL 约束语义、默认过滤被绕过或漏加、类型映射与边界值、批量族填充顺序、方言语义偏离、API 语义与文档不一致、错误类型与错误路径、会话状态泄漏、池租还与串租、缓存键完备性、拦截器调用次数、读写路由），3 类只有部分证据（取消传播只测会话层；事务隔离只测可见性不测隔离语义；行锁只测无事务调用）。
>
> 未覆盖的 3 类列在方案 §8.1（事务隔离级别、并发锁语义、大数据量计划退化）。首轮零失败结论限定在方案 §11 度量所记的覆盖范围内：432 个（操作，形状）对全部有处置（395 对可执行）、三方言、值样本 8 类、条件形态 8 种、手写 SQL 三套方言模板。该结论在 2026-10-29 追加的缺陷复核后被修正为 3 条已确认缺陷（见第五节之一）。
>
> 固定网格之外的输入由 D 层以 6 个固定种子 48 个场景加 1 个探索种子 12 个场景抽样，未发现缺陷不构成该范围的正确性证明。
>
> L6 跨方言判据在可比类型内成立，场景跳过 0 个；`DateTimeOffset` 因 MySQL 归一 UTC 而 SQLite 保留 offset，登记为列级不可比。
>
> 并发浸泡已按 §6.5 跑连续 3 轮 × 30 秒、三轮零违规。熔断三态仍只有部分证据（弹性执行器只对瞬时错误计数，SQL 错误不驱动，需瞬时错误注入才能覆盖三态转移）。
