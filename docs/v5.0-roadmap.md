## 实施路线（5 阶段，按依赖排序）

### 阶段 1：测试框架现代化（前置，最高风险先行）

TUnit 从 0.x 跨越到 1.x 稳定版，API 有重大变化。必须最先做，否则后续所有改动的测试验证都会受影响。

| 序号 | 项目 | 当前 | 目标 | 风险 | 工作量 |
|:---:|------|:---:|:---:|:---:|:---:|
| 1.1 | **TUnit 0.19.24 -> 1.61.15** | 0.19.24 | 1.61.15 | **高** | 大 |
| 1.2 | **TUnit.Assertions 0.7.9 -> ~1.61.x** | 0.7.9 | ~1.61.x | 高 | 大 |
| 1.3 | **移除 Microsoft.NET.Test.Sdk** | 17.13.0 | 删除 | 低 | 小 |
| 1.4 | **Microsoft.CodeAnalysis.Analyzers 5.3.0 -> 5.6.0** | 5.3.0 | 5.6.0 | 低 | 小 |
| 1.5 | **基准工具升级**（BenchmarkDotNet 0.15.8 / Dapper 2.1.79 / RepoDb 1.15.0） | 旧 | 最新 | 低 | 小 |

**1.3 说明**：`Microsoft.NET.Test.Sdk` 是 VSTest 经典模式 SDK。TUnit 基于 MTP（Microsoft.Testing.Platform）模式，用 `dotnet run` 执行，不需要 VSTest 桥接。当前 3 个测试项目都引用了它但从不使用 `dotnet test`。移除后减少构建依赖。

**验证**：全部 424 项测试用 `dotnet run` 通过。

**3.1 PG 连接串参数**（仅当用户未显式设置时追加）：

| 参数 | 值 | 收益 | [事实]来源 |
|------|-----|------|---------|
| `MaxAutoPrepare` | 100 | 查询延迟 -30~50%（自动预编译，跨连接复用） | Npgsql 官方文档 |

| `ReadBufferSize` | 16384 | 大结果集减少 socket read | Npgsql 性能文档 |
| `WriteBufferSize` | 16384 | 大值写入吞吐 | 同上 |
| `SslNegotiation` | Direct | PG 17+ 跳过 SSL 协商省 1 RTT（旧版降级） | Npgsql 10.0 Release Notes |
| `Enlist` | false | 跳过 TransactionScope 检查 | .NET ADO.NET 文档 |

**3.2 MySQL 连接串参数**（仅当用户未显式设置时追加）：

| 参数 | 值 | 收益 | [事实]来源 |
|------|-----|------|---------|
| `AutoEnlist` | false | 跳过 TransactionScope 检查 | MySqlConnector 文档 |
| `AllowLoadLocalInfile` | true | MySqlBulkCopy 前提（阶段 4 需要） | 同上 |
| `CancellationTimeout` | 5 | 软取消 5 秒后强制关闭，避免连接泄漏 | 同上 |
| `UseCompression` | false | 低延迟网络关闭压缩 | 同上 |
| `ConnectionReset` | false | 跳过 COM_RESET_CONNECTION | 同上 |
| `ServerRedirectionMode` | Preferred | Azure MySQL 直连后端 | Azure 文档 |

**3.3 SQLite PRAGMA**（在 `InitializeConnectionAsync` 中追加）：

```sql
-- 当前仅设：foreign_keys=ON
-- 追加：
PRAGMA synchronous=NORMAL;       -- WAL 下安全，减少 fsync
PRAGMA cache_size=-65536;       -- 64MB 页缓存（默认 2MB）
PRAGMA temp_store=MEMORY;       -- 临时表走内存
PRAGMA wal_autocheckpoint=1000; -- WAL 自动检查点
-- 仅文件数据库追加（:memory: 跳过）：
PRAGMA mmap_size=268435456;     -- 256MB mmap
```

**3.4 NpgsqlParameter\<T\>**：CommandFactoryEmitter 为 PG 路径新增 typed binder emit。值类型列使用 `NpgsqlParameter<T>.TypedValue` 替代 `(object)value`。非 PG 路径保持现有 `DbParameter.Value`。

**验证**：连接串调优 + PRAGMA 无行为变更（仅性能）。NpgsqlParameter\<T\> 需快照重生成 + 全量测试。

### 阶段 4：架构级驱动层改造

| 序号 | 项目 | 收益 | 风险 | 工作量 |
|:---:|------|------|:---:|:---:|
| 4.1 | **DbDataSource 单例化** | 统一池管理 + AOT 友好 | 中 | 中 |
| 4.2 | **MySqlBulkCopy 阈值分流** | 批量 4.84x | 中 | 中 |
| 4.3 | **DbBatch（BulkUpdate/Delete 批量化）** | 批量 2-4x | 中 | 中 |

**4.1 DbDataSource 单例**：

```
IDbProvider 新增：static virtual DbDataSource? CreateDataSource(DbOptions options) => null;

PostgreSqlProvider 覆盖：
  new NpgsqlSlimDataSourceBuilder(cs)  // AOT 友好（替代 NpgsqlDataSourceBuilder）
    { ConnectionStringBuilder = { MaxAutoPrepare=100, NoResetOnClose=true, ... } }
    .EnableJsonTypes()  // OwnedJson 需要
    .Build();

MySqlProvider 覆盖：
  new MySqlDataSourceBuilder(cs).Build();

SqliteProvider：返回 null（fallback 到 CreateConnection）

DataSession.CreateAsync：优先 DataSource.OpenConnectionAsync，fallback CreateConnection
DataSession.DisposeAsync：释放连接（不释放 DataSource——DataSource 是应用级单例）
```

**不做 Multiplexing**（与 SessionOperationState 独占连接冲突）。
**不做 `DataSource.CreateCommand()` 直接执行**（绕过 SessionOperationState）。

**4.2 MySqlBulkCopy**：`MySqlProvider.BulkInsertAsync` 新增阈值分流：

```csharp
if (entities.Count >= 2000)
    await MySqlBulkCopyAsync(entities);  // 二进制行协议
else
    await MultiValueInsertAsync(entities);  // 现有多值 INSERT
```

**4.3 DbBatch**：`BulkUpdateAsync` / `BulkDeleteAsync` 使用 `NpgsqlBatch` / `MySqlBatch`（单次往返）。SQLite 不支持 DbBatch，保持逐条。

### 阶段 3-4 深度审查补充（5 项）

#### 3.5 SQLite PRAGMA mmap_size 条件判断

`mmap_size` 仅对文件数据库有效，`:memory:` 数据库跳过。`InitializeConnectionAsync` 需检测连接串：

```csharp
bool isInMemory = connectionString.Contains("Mode=Memory", StringComparison.OrdinalIgnoreCase)
    || connectionString.Contains(":memory:", StringComparison.OrdinalIgnoreCase);
// 仅文件数据库追加 PRAGMA mmap_size
```

#### 3.6 SQLite Pooling/Cache 解除限制

当前代码（SqliteProvider.cs:30-31）拒绝任何 PoolExplicitlyConfigured 配置。但 MDS 的 `Pooling` 是 bool（不是数值），`Cache` 有 `Default`/`Private`/`Shared` 三态。

**改造**：解除 `PoolExplicitlyConfigured` 的 `NotSupportedException`，改为：
- `Pooling=true/false` — 按 `MaxPoolSize > 0` 映射
- `Cache=Shared` — 多连接共享 WAL 缓存（多线程读场景显著提升）
- 文档说明 SQLite 池语义与 PG/MySQL 不同

#### 4.4 Npgsql 10.0 RowFactoryEmitter 兼容性验证

**结论：不需要改 RowFactoryEmitter。**

RowFactoryEmitter 对 `DateTime` 列生成 `r.GetDateTime(ordinal)`。Npgsql 10.0 的 `date` 列通过 `GetDateTime()` 仍返回 `DateTime`（内部转换），只有 `GetValue()` / `GetFieldValue<DateOnly>()` 才返回 `DateOnly`。

PalORM 的 `DateOnly` emit 路径（行 154）已经是 `DateOnly.FromDateTime(r.GetDateTime(ordinal))`，兼容。

**验证要求**：Npgsql 10.0 升级后必须跑 PG 集成测试（`dotnet run --project test/PalORM.Integration.Tests` 带 `PALORM_PG_CONNECTION`），确认 `date`/`time`/`timestamp` 列读写正常。

#### 4.5 Npgsql EnableJsonTypes() 不需要

PalORM 的 OwnedJson 使用自己的 `JsonSerializerContext` + 源生成器 emit，不走 Npgsql 的 JSON 类型映射。因此 `NpgsqlSlimDataSourceBuilder` **不需要调用 `EnableJsonTypes()`**。

验证：OwnedJson 测试在 Npgsql 10.0 + SlimBuilder 下通过即确认。

#### 4.6 global.json rollForward 调整

当前 `rollForward: disable`，只接受精确的 preview.6 SDK。v5.0 建议改为 `latestMinor`，允许 SDK 补丁版本（如 preview.6.1、preview.7）自动前滚：

```json
{
  "sdk": {
    "version": "11.0.100-preview.6.26359.118",
    "rollForward": "latestMinor",
    "allowPrerelease": true
  }
}
```

## 不做项（含论证）

| 项目 | 理由 |
|------|------|
| **AsyncState 合并** | v4.6 owner=this 已让 EC 拷贝短路（~0B），引入依赖破坏零依赖 + AOT 风险 |
| **轻量 DataSession** | 改动=重写半个 PalORM，收益 ~312B 占比 <10%，事务仍需独占连接 |
| **SQLite P/Invoke** | 破坏三 Provider 统一架构，ROI 极差 |
| **DbCommand 对象复用** | ~120B/查询（2.4%），生命周期管理复杂 |
| **热查询自动 Prepare** | MDS Prepare 是 no-op（不缓存 stmt）；PG MaxAutoPrepare 已在驱动层自动做 |
| **SQLite 单条 INSERT 循环** | MDS 不跨命令缓存 stmt（EF Core #14044 确认），10K 次 async 开销远大于 30 次多值 INSERT |
| **CommandBehavior.SequentialAccess** | SQLite 内存数据库无 I/O 等待，async 读取增加状态机开销 |
| **DbParameter.Size 显式设置** | 源生成器编译期无法推断运行时字符串长度 |
