# PalORM v5.0 需求规划

> 基于 v4.0-v4.6 开发过程中积累的全部调研、审计、讨论结论。

---

## 一、性能优化（Provider 驱动层）

### P0: PostgreSQL 连接串调优

- `MaxAutoPrepare=100` / `AutoPrepareMinUsages=2` — 查询延迟 -30~50%
- `NoResetOnClose=true` — 归还连接跳过 DISCARD ALL，+30% localhost 吞吐
- `ReadBufferSize=16384` / `WriteBufferSize=16384` — 大结果集减少 socket read

**方案**: DbOptions 新增 PG 连接串性能参数，或 PostgreSqlProvider.CreateConnection 追加。

### P0: MySQL 连接串调优

- `AllowLoadLocalInfile=true` — MySqlBulkCopy 前提
- `CancellationTimeout=5` — 软取消 5 秒后强制关闭，避免连接泄漏
- `UseCompression=false` — 低延迟网络关闭压缩（CPU 换带宽不划算）
- `ConnectionReset=false` — 跳过 COM_RESET_CONNECTION（确认不依赖连接状态隔离时）

**方案**: MySqlProvider.CreateConnection 追加性能参数。

### P0: SQLite PRAGMA 调优

当前 `InitializeConnectionAsync` 仅设 `journal_mode=WAL` + `foreign_keys=ON`。追加：

- `synchronous=NORMAL` — WAL 模式下安全，减少 fsync 次数，写性能提升
- `cache_size=-8000` — 8MB 页缓存（默认 2MB），读命中率提升
- `temp_store=MEMORY` — 临时表/排序走内存
- `mmap_size=268435456` — 256MB mmap（仅文件数据库有效，`:memory:` 无意义）

**方案**: SqliteProvider.InitializeConnectionAsync 追加 PRAGMA。

### P0: NpgsqlParameter<T> 零装箱

- 值类型列（long/int/decimal/double）使用 `NpgsqlParameter<T>.TypedValue` 替代 `DbParameter.Value = (object)`
- 源生成器 emit 检测 Provider 类型，PG 路径走泛型参数
- 预期：每行每值类型列省 24-32B 装箱

**方案**: CommandFactoryEmitter 新增 PG 专属 emit 路径。

### P1: MySqlBulkCopy 替代多值 INSERT

- 行数 > 阈值（500+）时走 `MySqlBulkCopy`（LOAD DATA LOCAL INFILE 协议）
- 实测 4.84x 加速 vs 多值 INSERT
- 前提：连接串 `AllowLoadLocalInfile=true` + 服务端 `local_infile=1`

**方案**: MySqlProvider.BulkInsertAsync 新增 BulkCopy 路径。

### P2: DbBatch API（.NET 6+）

- NpgsqlBatch / MySqlBatch 单次往返执行多条命令
- BulkUpdate/BulkDelete 从逐条改为批量
- SQLite 不支持 DbBatch，保持多值 INSERT

## 二、功能增值（协调层独有能力）

### P1: 单操作级 timeout/retry override

- SessionOperationLease 新增 `TimeoutOverride` / `RetryOverride` 字段
- 昂贵写入用 0 重试，幂等读取用 3 重试，互不干扰
- 避免级联重试风暴

**方案**: EnterOperation 接收 override 参数，ExecuteAsync 读取。

### P1: 会话级 SET 一次性执行

- `SetSearchPath("tenant_x, public")` / `SetTimeZone("UTC")`
- 连接首次激活时执行一次，不每查询重复
- Dapper 做不到（无连接生命周期管理）

**方案**: DbOptions 新增 `SessionSetupSql`，CreateAsync 后执行。

### P2: Audit Interceptor

- 基于 IQueryInterceptor，自动记录每条 SQL 的开始/结束/耗时/影响行数
- 输出到 ILogger 或自定义 sink

### P2: ForUpdate(skipLocked) / AdvisoryXactLock

- QueryBuilder 新增 `ForUpdate(skipLocked: true)` 便捷方法
- PG `pg_advisory_xact_lock(key)` 支持

## 三、易用性增强

### P1: Scaffold 工具增强

- 支持 PostgreSQL / MySQL（当前仅 SQLite）
- 自动检测 `deleted_at` 列生成 `[SoftDelete]`
- 自动检测 `tenant_id` 列生成 `[TenantAware]`
- 支持生成 `[OwnedJson]`（检测 JSON/JSONB 列类型）

### P2: ASP.NET Core 集成包

- `PalORM.AspNetCore` 包
- `AddPalORM<TProvider>(connectionString)` DI 扩展方法
- `IDbOptionsSource` 从 IConfiguration 自动映射
- HealthCheck 集成（`PalORMHealthCheck`）

### P2: 连接池监控

- DbOptions 暴露连接池统计（活跃/空闲/等待）
- OTel 指标对齐（`palorm.pool.active` / `palorm.pool.idle`）

## 四、架构演进（评估项）

### 评估: SessionOperationState 进一步优化

- v4.5 已做 TCS 延迟创建 + Exit 不写 AsyncLocal（-388B/操作）
- v4.6 已做 owner=this + EC 相等短路（-324B/操作）
- 剩余 ~300B EC 拷贝是 AsyncLocal 语义的固有代价
- **评估是否值得引入 `Microsoft.Extensions.AsyncState` 合并 2 个 AsyncLocal 为 1 个**

### 评估: 轻量 DataSession（可选模式）

- 新增 `PalOrmClient` 类，每次操作从 ADO.NET 驱动池借连接
- 零协调层（无 SessionOperationState）
- 支持 GridReader/QueryAsyncEnumerable/WithTransaction 的连接粘性
- **风险**: 改动面大（45+ 方法），需评估是否值得

### 评估: NpgsqlDataSource 单例

- Npgsql 官方推荐：`NpgsqlDataSource` 应作为单例使用
- 统一连接池管理，避免多实例多池
- 支持 `dataSource.CreateCommand()` 直接执行（跳过连接租借）
- **注意**：Multiplexing 与 SessionOperationState 独占连接设计冲突，**不做 Multiplexing**
- DataSource 单例本身有价值（统一池管理 + 连接生命周期钩子）

### 不做: SQLite P/Invoke

- 直接调 `sqlite3_bind_int64` 等绕过 ADO.NET
- 破坏三 Provider 统一架构
- 只对 SQLite 有效，ROI 极差

### 不做: DbCommand 对象复用

- 每次 CreateCommand 分配 ~120B，占 4.97KB 的 2.4%
- 生命周期管理复杂（跨 connection 报错、并行冲突）
- ROI 低

### 不做: 热查询自动 Prepare

- `Microsoft.Data.Sqlite.Prepare()` 是 no-op，不缓存 statement
- PG 的 `MaxAutoPrepare` 已在驱动层自动做
- ORM 层 LRU 计数与驱动自动预编译重复

| P1 | 单操作 timeout/retry override | 灵活策略控制 |
| P1 | 会话级 SET | 每连接省 N 次 RTT |
| P1 | Scaffold 增强 | 三 Provider 支持 |

| P2 | Audit Interceptor | 合规审计 |
| P2 | ForUpdate(skipLocked) | 队列式负载 |
| P2 | ASP.NET Core 集成 | DI + HealthCheck |
| 评估 | AsyncState 合并 | -300B EC 拷贝 |
| 评估 | 轻量 DataSession | 零协调层 |
| 评估 | NpgsqlDataSource 单例 | 统一池管理（不做 Multiplexing） |
| 不做 | SQLite P/Invoke | ROI 极差 |
| 不做 | DbCommand 复用 | ROI 低（~120B/2.4%） |
| 不做 | 热查询自动 Prepare | MDS no-op / PG 已有 |
