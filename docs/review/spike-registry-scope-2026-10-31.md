# Spike：RegistryScope 与模块化单体

- 日期：2026-10-31
- 结论：保持进程级全局注册表；`RegistryScope` 暂不实施
- 定位：设计评估，不产生代码变更

## 现状

| 组件 | 作用域 | 影响 |
|------|--------|------|
| `PalORM_Runtime` | 进程级静态 | 所有实体注册到同一张表，`MigrateAsync` 迁移全集 |
| `EntityInfoCache.Per<T>` | 进程级按类型 | 同一类型只能有一份元数据 |
| `SqlSlots<T>` | 进程级按 `(TProvider,T)` | 同一类型的 SQL 槽跨会话共享 |
| `DataSessionCache` | 进程级按 `(Type,Dialect)` | 同一类型的过滤/形状缓存共享 |
| `From<T>()` | 会话级构建器 | 元数据来自全局注册表 |

## 选项

| 选项 | 内容 | 成本 | 风险 |
|------|------|------|------|
| A 保持全局 | 每个进程一个注册表 | 零 | 多上下文共享表名/迁移 |
| B 会话级注册视图 | `DataSession` 绑定一个注册表快照 | 高 | `EntityInfoCache`/`SqlSlots` 需按注册表身份分片 |
| C 模块级片段过滤 | 注册时打模块标签，`MigrateAsync` 按模块过滤 | 中 | 生成代码与注册链需携带标签 |

## 评估

1. 选项 B 会改变 `From<T>()` 的热路径：静态缓存键从 `(TProvider,T)` 变为 `(RegistryIdentity,TProvider,T)`，所有静态槽需要增加一维，缓存命中率与内存占用都会受影响。
2. 选项 C 只能解决迁移过滤，不能解决同一类型在不同上下文使用不同表名的冲突。
3. 当前 `[Table]` 名称是编译期常量，同一类型无法在不同上下文映射到不同表名；真正的多上下文隔离需要不同的持久化类型或不同的进程/数据库。
4. 模块化单体的现实做法是每个上下文独立数据库或独立进程，或使用表名前缀并在部署层隔离。

## 建议

保持选项 A。在架构文档中明确：一个进程对应一个注册表与一个逻辑数据库；模块化单体需要多上下文时，优先使用独立进程/数据库，或在应用层做表名前缀与迁移过滤，不把注册表作用域引入 Core。
