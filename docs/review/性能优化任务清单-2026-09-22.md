## 八、验收硬门槛

1. **仪器必须先能失败**。每个修复项的验收测试，改前先跑一次确认它红（例：NOTIF-001 的现状断言 `DisposeCount == 1` 与死亡路径兼容，5/5 通过毫无意义）。测试体系级有效性用 `scripts/run-mutation-tests.sh`（Stryker.NET，门槛 >80%）。

3. **CI"确实执行了"**：`bash scripts/assert-test-counts.sh <项目名> <tunit-report.json>`（passed ≥ 地板、skipped == 0、Integration 真库用例数 ≥ 地板）。
4. **文档一致性**：`bash .ai/scripts/doc-consistency-check.sh`（本地工具）；凡改公共 API、签名、行为、计数、配置项，同一次提交内同步代码 + XML doc + 注释 + `docs/`（三方一致）。计数口径全仓库统一（step5 的 43/52 即反面教材）。
5. **构建门禁**：`dotnet build PalORM.ci.slnf -c Release --no-incremental -warnaserror` 零警告；Core / SourceGen / Integration 三套件不回退；AOT 矩阵保持绿。快照类改动先 `PALORM_UPDATE_SNAPSHOTS=1 dotnet run` 确认基线，再人工审阅 diff。
6. **收益标注纪律**：未实测的收益保持 `[推断]`，不得写入规范；实测证伪的条目从本账本划除并记录原因，不保留"理论收益"。
