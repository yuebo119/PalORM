## 架构决策记录

- 运行时实体元数据由单一不可变状态承载；`Register(RegistryFragment)` 在锁内构造完成后一次发布，公开注册表属性改为只读。
- `ColumnNames`、`InsertColumns` 和 `UpsertColumns` 在注册边界防御性复制，fragment 持有者不能篡改已发布元数据。
- 删除只写不读的 `GlobalNamingConvention`；命名策略仅由 `DbOptions.NamingConvention` 实例持有。
- 直接给 `PalORM_Runtime` 注册表属性赋值不再受支持，外部扩展应迁移到 `Register(RegistryFragment)`。
- 包版本已提升至 2.0.0：旧 setter、数组字段和 `CrudMetadata` 构造函数的 CLR 签名已改变，1.x 已编译消费者必须重新编译。
- SourceGen 编译期生成 SQLite、PostgreSQL、MySQL 三套已引用 CRUD SQL 和 DDL；运行时按静态 Provider 方言选择，旧 `CommandSqlSet` / `CreateTableSql` 保留兼容。
- 实体查询显式投影生成列顺序，JOIN 的根实体列和表达式排序列使用限定名；MySQL 仅对数值自增键调用 `LAST_INSERT_ID(expr)`。
- 三 Provider BulkInsert 统一使用源生成 `InsertColumns` / `BindInsert` 并预检参数形状；BulkDelete 通过生成主键 binder 支持 Converter，SoftDelete 实体批量更新 `deleted_at`。
- 零可插入列和零可更新列在数据库访问前明确失败；key-only Save 使用合法幂等冲突分支。
- DataSession、QueryBuilder 与 QueryMultiple 共用 Formattable SQL formatter；BCL 验证复合格式语法，alignment 与 format specifier 不改变参数原对象。
- 三 Provider BulkInsert 的 probe、row/main command、rollback 与 transaction cleanup 均保留主异常；清理异常通过 `Exception.Data` 附加。
- DataSession、QueryBuilder、Bulk、StoredProc 和 GridReader 共用单消费者 operation state；重叠操作 fail-fast，Dispose 等待活动命令、GridReader 和事务 scope。
- GridReader 采用单活动读取、幂等释放和共享 disposal task；`WithTransaction` 拒绝嵌套与 sibling flow，并保留 action/commit 主异常。

详见 `docs/架构设计.md` 第 18 项最优设计决策。
