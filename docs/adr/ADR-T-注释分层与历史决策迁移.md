# ADR-T：注释分层与历史决策迁移

- 状态：已采纳（2026-10-31）
- 适用范围：`src/PalORM.Core/DataSession*.cs`、`QueryBuilder.cs`、`DataSession_Bulk.cs` 及后续热路径文件

## 背景

PalORM 的热路径代码承载了大量历史信息：ITM 编号、探针实测数字、被否决方案、历次审计结论。这些注释在缺陷定位与回归防护上价值很高，但同时带来两个问题：

1. 方法上方注释密度过高，阅读者需要穿过历史才能看到当前不变量；
2. 历史数字与轮次容易过期，代码改动后注释与实现漂移，形成第二真源。

## 决策

注释分三层，按信息类型归位：

| 层 | 位置 | 内容 | 例子 |
|----|------|------|------|
| 当前不变量 | 方法或字段上方 | 现在必须成立的契约、失败语义、性能依据 | “复用命令不得 Clear/Add 参数集合，R-UNNESTB” |
| 历史决策 | `docs/adr/`、`.ai/lessons.md`、`.ai/perf-ledger.md` | 轮次、探针数字、被否决方案、复现条件 | “B95 比值分母失效的判定” |
| 可追溯指针 | 代码注释一行 | 指向历史决策的 ADR 或 lessons 编号 | “历史测量见 ADR-T” |

约束：

1. 仍对实现有约束力的警告不得删除。R-UNNESTB、EC 包含、命令复用晋升阈值、连接态标脏等属于当前不变量，保留在代码注释中。
2. 历史数字只在 ADR/账本中维护；代码注释不再复制易变测量值。
3. 迁移顺序：先建立 ADR/账本条目，再精简代码注释。禁止先删注释后补文档。
4. 每次精简只动一个方法或一个注释块，行为零变化，构建与测试全绿后提交。

## 历史块迁移索引

| 代码位置 | 历史主题 | 归位 |
|----------|----------|------|
| `DataSession_Bulk.cs` 批量删除/更新/合并段 | UNNEST、json_each、MySQL ODKU、批宽实测 | ADR-P、ADR-Q、ADR-R、`.ai/perf-ledger.md` |
| `QueryBuilder.cs` WhereIn/Join/CTE 段 | v5.6 单缓冲、CTE 重限定、OR/AND 分组修复 | 本 ADR 与 `.ai/lessons.md` |
| `DataSession.cs` 会话门禁/池化段 | EC 包含、G2 塌方、池化复位、复用槽 | `.ai/lessons.md` B 系列、`.ai/perf-ledger.md` |
| `DataSession.Schema.cs` 迁移段 | L4 批处理、并发建表竞态、事务化 | 本 ADR 与 `DataSession.Schema.cs` 当前不变量注释 |

## 后果

- 代码注释更短，当前不变量更醒目；历史信息仍可通过 ADR/账本检索。
- 需要维护 ADR 与代码指针的一致性；文档一致性检查覆盖版本、测试计数、门禁与诊断计数，注释指针目前靠人工评审。
- 本次只完成规范与首个示范块的精简，其余历史块按索引逐步迁移，避免一次性大规模删除造成知识丢失。
