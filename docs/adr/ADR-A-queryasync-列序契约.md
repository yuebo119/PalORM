# ADR-A：QueryAsync 原生 SQL 列序契约

> 状态：提议（2026-07-17）· 来源：评审 ITM-117/150（GEN-06）

## 背景

`QueryAsync<T>(FormattableString)` 把用户任意 SQL 的结果直接喂给源生成 RowFactory，RowFactory 按 ordinal 读取（`GetXxx(0..n)` 对应实体声明序）。用户 SQL 列序与实体声明序不同且相邻列同型时**静默交换数据**——这是用户 SQL 入口的 P0 型危害面。`SELECT *` 依赖物理表列序，迁移加列后立即错位。

QueryBuilder 路径（`From<T>()`）不受影响：SELECT 列序由编译期元数据生成，构造性安全。

## 现状（2026-07-17 已实施的缓解）

`QueryAsync` XML 文档已显式声明列序契约：按 ordinal 映射、要求显式列清单按实体声明序、警告 `SELECT *`。

## 选项

| 选项 | 机制 | 优点 | 缺点 |
|------|------|------|------|
| A1 按序读取（现状+文档契约） | RowFactory ordinal 直读 | 零开销；契约已文档化 | 契约靠自觉，错位静默 |
| A2 列名映射 | 生成 `Read(reader, ordinalMap)` 重载，执行时按 `GetOrdinal` 建映射 | 列序无关，安全 | 每查询一次映射构建开销；列名不匹配需决定报错或跳过 |
| A3 双模式 | 默认 A1；`QueryAsync<T>(sql, byName: true)` 走 A2 | 用户按需换安全性 | API 面扩大；生成器需同时生成两套读取 |
| A4 首行校验 | A1 + 首行 `GetName(i)` 与元数据列名比对，不匹配抛异常 | 错位 fail loud 而非静默；开销仅首行 | 别名/表达式列（`COUNT(*) AS c`）需豁免规则 |

## 推荐

**A4（首行校验）**：保持热路径零开销，把"静默换数据"变为"明确失败"，与项目"明确失败优于静默错误"的既有哲学一致。校验可经 `DbOptions` 开关（默认开，性能敏感者可关）。A2/A3 留作后续增强。

## 待用户决策

- 若 A4：校验失败是抛异常还是 `ILogger` 警告？
