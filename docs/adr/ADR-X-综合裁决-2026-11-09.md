## DEC-1：IgnoreFilters 写语义 → **A（写侧也放开，文档化 + 锁定测试）**

- **现状**：读侧跨租户有意（ADR-L 明示，运维/报表读全量）；**写侧同样跳过租户条件，但无文档、无测试**。
- **裁决**：**A（写侧也放开，改文档）**。
- **理由**：`IgnoreFilters()` 是显式调用，调用方知道自己在关闭过滤；真正的风险是写侧语义**无声明、无锁定**，后续易被无声改动。曾评估 B（写侧恒租户过滤），但它会堵死跨租户批量运维——`WithTenant(null)` 被显式拒绝（ITM-532：null 会让租户过滤静默关闭），`IgnoreFilters()` 是当前**唯一**能清空租户过滤的入口；若采 B 必须同时提供显式出口（新 API），属设计变更，需单独立项。
- **落地**：① `docs/功能特性.md` §10 写明「该开关读写都生效」；② 加锁定测试固定当前行为；③ 触发条件：出现「同一会话先 `IgnoreFilters()` 再执行写」的真实用法时，启动 B 并连同出口设计。

## DEC-2：AllowLoadLocalInfile → **A（维持 ADR-G）**

- **现状**：显式 false 被覆盖，ADR-G 维持（安全优先）。
- **裁决**：**A（维持 ADR-G）**。
- **理由**：`local_infile` 是安全敏感开关，显式声明不应被静默覆盖；维持"显式 false 不生效"的保守语义，避免 LOAD DATA 的本地文件读取面。
- **落地**：不改代码，维持现状（ADR-G 已记录）。

## DEC-3：upsert 三方言差异 → **A（补文档 + 测试锁定）**

- **现状**：MySQL 静默覆盖 vs PG/SQLite 抛错。
- **裁决**：**A（补文档 + 测试锁定）**。
- **理由**：各方言原生语义不同（MySQL `ON DUPLICATE KEY UPDATE` vs PG/SQLite 的冲突抛错），强行对齐会牺牲 MySQL 的性能路径。用文档与测试锁定差异，调用方显式选择。
- **落地**：API 参考与升级指南记录三方言差异；测试锁定各方言行为。

## DEC-4：PG DateTimeKind → **A（归一 UTC）**

- **现状**：`DateTime.Kind=Local` 时抛异常 vs 静默写入。
- **裁决**：**A（归一 UTC）**。
- **理由**：与列型 `timestamptz`（本版已改）语义一致；`DateTime` 在 PG 上统一表示 UTC 时刻，避免本地时区静默偏移。`Kind=Unspecified` 按 UTC 处理（与 Npgsql 默认一致）。
- **落地**：PG 参数绑定处把 `DateTime` 归一为 UTC（`DateTime.SpecifyDateTime(value, DateTimeKind.Utc)`），`Kind=Local` 先转 UTC。
