# PalORM 测试规范（SOP）

> 本规范定义 PalORM 项目的测试执行标准。所有贡献者在提交 PR 前必须遵守。

## 一、提交前必检清单

```bash
# 1. 构建（0 警告 0 错误）
dotnet build PalORM.slnx -c Debug --no-incremental

# 2. 单元测试（全绿）
dotnet test test/PalORM.Core.Tests --nologo
dotnet test test/PalORM.SourceGen.Tests --nologo

# 3. 集成测试（SQLite 路径全绿）
dotnet test test/PalORM.Integration.Tests --nologo

# 4. 技术债扫描（12/12，本地工具 .ai/scripts/tech-debt-scan.sh）
```

**外部数据库测试**（PG/MySQL）可选，需要 `.env.test` 配置：
```bash
source scripts/set-test-env.sh  # 或手动 export
dotnet test test/PalORM.Integration.Tests --nologo
```

## 二、新增代码的测试要求

| 代码类型 | 必须的测试 | 测试项目 |
|---------|-----------|---------|
| `src/PalORM.Core/*.cs` 新增方法 | 至少 1 个正向 + 1 个边界 + 1 个异常 | `test/PalORM.Core.Tests` |
| `src/PalORM.SourceGen/*Emitter.cs` emit 变更 | 快照基线重生成 + 断言 emit 内容 | `test/PalORM.SourceGen.Tests` |
| `src/PalORM.SourceGen/PalORMAnalyzer.cs` 新诊断 | 至少 1 个触发 + 1 个不触发 | `test/PalORM.SourceGen.Tests` |
| 新 Provider 适配 | 至少 1 个 DryRun + 1 个真库冒烟 | `test/PalORM.Integration.Tests` |
| 性能敏感路径 | 对应的 `[Benchmark]` | `bench/PalORM.Benchmarks` |

## 四、BenchmarkDotNet 配置选择

| 场景 | 命令 | 配置 | 耗时 |
|------|------|------|:---:|
| 开发迭代验证 | `bash scripts/run-benchmarks.sh sqlite` | 1/3/5 | ~5min |
| 正式报告 | SqliteBenchmarks 类内置 | 3/5/10 | ~15min |
| nanosecond 级微基准 | SqlBuildBenchmarks 类内置 | 5/10/15 + invocation | ~10min |
| 拐点扫描 | `bash scripts/run-benchmarks.sh scale` | 1/3/5 × 4 Params | ~10min |
| 纯速度交叉验证 | `bash scripts/run-benchmarks.sh speed` | 3/5/10 无 Diagnoser | ~8min |
| 发版基线 | `--save-baseline` | 标准 + 严格 | ~30min |

## 五、统计有效性判据

```
Error / Mean < 5%   → 统计有效，可用于正式报告
Error / Mean 5-15%  → 可接受，报告需标注「环境敏感」
Error / Mean > 15%  → 统计无效，必须：
  (1) 提升配置（launchCount / iterationCount）
  (2) 排查噪声源（后台进程 / 散热 / VMware）
  (3) 考虑改用纯速度基准（无 MemoryDiagnoser）
```

## 六、源生成器变更的特殊规则

> emit 模板变更是高风险操作——旧 obj 缓存会导致增量构建复用旧 emit。

```bash
# 改 RowFactoryEmitter / CommandFactoryEmitter / RegistryEmitter / MigrationEmitter 后必须：
rm -rf src/*/obj src/*/bin test/*/obj test/*/bin bench/*/obj bench/*/bin
PALORM_UPDATE_SNAPSHOTS=1 dotnet test test/PalORM.SourceGen.Tests
# 评审 git diff 的快照变更，确认 emit 差异符合预期
git diff test/PalORM.SourceGen.Tests/Snapshots/
```

## 七、PR 性能影响评估

PR 涉及 `src/PalORM.Core/` 或 `src/PalORM.SourceGen/` 的性能敏感路径时：

```bash
# 1. PR 分支跑基准
bash scripts/run-benchmarks.sh sqlite --save-baseline

# 2. 切到 main 跑基线
git stash && git checkout main
bash scripts/run-benchmarks.sh sqlite

# 3. 人工对比两份 JSON 快照
# 关键指标：Median 回归 >10% 需在 PR 说明原因
```

PR 标签 `[perf]` 会自动触发 CI `perf-gate.yml`。

## 八、AOT 变更验证

涉及以下文件时必须验证 AOT：

| 文件 | 风险 | 验证命令 |
|------|:---:|---------|
| 任何 `src/` 下的反射/API | 高 | `dotnet publish test/PalORM.AotTest -p:PublishAot=true` |
| `System.Text.Json` 相关 | 高 | 确认 `[JsonSerializable]` context 存在 |
| `Convert.ChangeType` 路径 | 中 | 确认 TValue 是 IConvertible 基元 |
| 新增 `[Table]` 实体 | 低 | 确认 `partial class` + public 无参 ctor |

## 九、CI Pipeline 触发规则

| Workflow | 触发条件 | 作用 |
|----------|---------|------|
| `ci.yml` Build & Test | 每次 push/PR | 构建 + 单元 + 集成 + 质量门禁 |

| `perf-gate.yml` | 每周日 + `[perf]` PR | SQLite 基准 + 基线回归检测 |
