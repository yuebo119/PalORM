# 方案：向量搜索支持（AI/RAG 场景）

> 状态：**草案** · 优先级：P1（趋势）/ P2（当前）· 目标版本：v6.0
> 来源：行业趋势调研 2026-07-28 · 严格遵循 B28「特性推荐四问」

## 一、背景与动机

### 1.1 行业趋势（[事实]）

**EF Core 9（2024）+ 10（2025）已原生支持向量搜索**：
- [事实] EF Core 9 支持 pgvector（[Telerik: Vector Search with EF 9](https://www.telerik.com/blogs/vector-search-ef-9)）
- [事实] EF Core 10 支持 SQL Server 2025 `vector` 类型 + `VECTOR_DISTANCE()` 函数（[Microsoft Learn: What's New in EF Core 10](https://learn.microsoft.com/ef/core/what-is-new/ef-core-10.0/whatsnew)）
- [事实] Microsoft Semantic Kernel PG 连接器支持 `ReadOnlyMemory<float>` 向量属性（[Microsoft Learn: Postgres Connector](https://learn.microsoft.com/semantic-kernel/concepts/vector-store-connectors/out-of-the-box-connectors/postgres-connector)）

**micro-ORM 阵营现状**（[事实] 调研）：
- Dapper：通过第三方 `Pgvector.Dapper` 包支持（type handler 模式）
- RepoDB：不支持
- Linq2Db：不支持

**结论**：向量搜索是 AI/RAG 时代主流需求，EF Core 已证明这是"必备能力"而非"可选特性"。PalORM 作为 micro-ORM 若补齐这是**差异化机会**（比 RepoDB/Linq2Db 领先，与 Dapper 持平但跨方言更优）。

### 1.2 B28 四问过滤

| 问 | 答 |
|----|-----|
| ① ORM 职责吗？ | ✅ SQL 生成 + 参数绑定是 ORM 核心职责。向量距离查询是新型 SQL 谓词 |
| ② AOT 可行吗？ | ✅ `ReadOnlyMemory<float>` 是值类型，源生成器可零反射处理 |
| ③ 客户自建更好吗？ | ⚠️ 部分——客户可用 `Raw("<=> @p")` 手写，但 embedding 列映射重复劳动；ORM 抽象有价值 |
| ④ 真必需吗？ | ⚠️ 趋势是（EF Core 9/10 已做），当前视用户群而定 |

**结论**：通过四问。**不是 P0**——当前用户群 AI 应用比例未知；但**建议 v6.0 做**作为趋势布局。

## 二、技术调研

### 2.1 PG pgvector 机制（[事实] [pganalyze](https://pganalyze.com/blog/5mins-postgres-vectors-pgvector)）

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 建表（1536 维 = OpenAI text-embedding-ada-002）
CREATE TABLE items (id BIGSERIAL PRIMARY KEY, embedding vector(1536));

-- 插入
INSERT INTO items (embedding) VALUES ('[0.1, 0.3, 0.5]');

-- 最近邻查询（KNN）
SELECT id, embedding <=> '[0.1, 0.3, 0.5]' AS distance  -- 余弦距离
FROM items ORDER BY embedding <=> '[0.1, 0.3, 0.5]' LIMIT 10;

-- 也可用：
-- <->  欧几里得距离 (L2)
-- <#>  负内积
```

**三种距离运算符**：
| 运算符 | 含义 | 适用场景 |
|--------|------|----------|
| `<->` | L2 欧几里得距离 | 图像相似度 |
| `<=>` | 余弦距离 | 文本语义搜索（最常用） |
| `<#>` | 负内积 | 已归一化向量的点积 |

**索引**：HNSW（默认）或 IVFFlat。

### 2.2 SQLite sqlite-vec 机制（[事实]）

SQLite 的向量扩展（`sqlite-vec`），语法与 pgvector 不同：

```sql
-- 启用扩展（需 .load_extension）
CREATE VIRTUAL TABLE vec_items USING vec0(embedding float[1536]);

-- KNN 查询
SELECT id, distance
FROM vec_items
WHERE embedding MATCH '[0.1, 0.3, 0.5]'
  AND k = 10
ORDER BY distance;
```

### 2.3 MySQL 现状（[事实]）

**MySQL 9.7（LTS）无原生向量类型**。替代方案：
- 存 `JSON` 数组 + 应用侧计算（极慢，无索引）
- 等 MySQL HeatWave 向量功能（企业版，未进入 Community）

**结论**：MySQL 暂不支持。

### 2.4 .NET 生态的 pgvector 客户端（[事实] [pgvector-dotnet](https://github.com/pgvector/pgvector-dotnet)）

```csharp
// 官方 Pgvector.Dapper 包通过 TypeHandler 模式
SqlMapper.AddTypeHandler(new VectorTypeHandler());
var dataSourceBuilder = new NpgsqlDataSourceBuilder(connString);
dataSourceBuilder.UseVector();  // 注册向量类型映射
await using var dataSource = dataSourceBuilder.Build();
```

**痛点**：
1. 需要 `NpgsqlDataSourceBuilder.UseVector()` 注册类型——PalORM 当前用 `new NpgsqlConnection(cs)`，需用户自行初始化（或走 PalORM 的连接串路径，见下文）
2. TypeHandler 是运行时映射——AOT 下需要确认安全性

## 三、技术方案

### 3.1 设计原则

**复用现有基础设施**，不引入新概念：
- 复用 `[Converter]` 值转换器机制（[事实] `Annotations.cs:147` 已存在）
- 复用 `QueryBuilder<T>` 链式 API
- 复用 SourceGen 现有 RowFactoryEmitter/CommandFactoryEmitter

**方言感知**：PG / SQLite 支持原生向量；MySQL 标记不支持并抛 `NotSupportedException`。

### 3.2 API 设计

#### 3.2.1 实体定义（注解）

```csharp
[Table("documents")]
public class Document
{
    [Key] public long Id { get; set; }
    public string Content { get; set; } = "";
    
    // 新注解：向量列
    [VectorColumn(dimensions: 1536, DistanceFunction.Cosine)]
    public ReadOnlyMemory<float> Embedding { get; set; }
}

/// <summary>新注解：标记向量列。</summary>
[AttributeUsage(AttributeTargets.Property)]
public sealed class VectorColumnAttribute(int dimensions) : Attribute
{
    public int Dimensions { get; } = dimensions;
    public VectorDistanceFunction DistanceFunction { get; init; } = VectorDistanceFunction.Cosine;
}

public enum VectorDistanceFunction { Euclidean, Cosine, NegativeInnerProduct }
```

#### 3.2.2 查询 API

```csharp

        ReadOnlyMemory<float> queryVector,
        VectorDistanceFunction distanceFunction = VectorDistanceFunction.Cosine)
        where T : class, new()
    {
        // 生成 ORDER BY "embedding" <=> @p0 LIMIT N（具体运算符按方言 + DistanceFunction 分支）
        // 参数绑定 ReadOnlyMemory<float> → Provider 通过 Converter 转为 vector 类型
    }
}
```

**用法**：

```csharp
var embedding = await openAi.GenerateEmbeddingAsync("搜索文本");
var results = await session.From<Document>()
    .OrderByVectorDistance(d => d.Embedding, embedding, VectorDistanceFunction.Cosine)
    .Take(10)
    .ToListAsync();
```

#### 3.2.3 迁移 DDL（MigrationEmitter 扩展）

```sql
-- PG 方言生成
CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding vector(1536) NOT NULL  -- 使用 pgvector 类型
);

-- SQLite 方言生成
CREATE VIRTUAL TABLE documents USING vec0(
    id INTEGER PRIMARY KEY,
    content TEXT NOT NULL,
    embedding float[1536]
);

-- MySQL 方言：PALORM 编译期告警 PALORM041（向量列不支持当前方言）
```

### 3.3 方言分支实现

#### PG 方言（pgvector）

**SQL 生成**：
```csharp
// SqlDialect.PostgreSql
string op = distanceFunction switch {
    VectorDistanceFunction.Euclidean => "<->",
    VectorDistanceFunction.Cosine => "<=>",
    VectorDistanceFunction.NegativeInnerProduct => "<#>",
    _ => throw new ArgumentOutOfRangeException(nameof(distanceFunction))
};
return $"ORDER BY {quotedColumn} {op} {paramName}";
```

**参数绑定**：
- 模式 A（推荐）：依赖用户预初始化（`CREATE EXTENSION vector` + 连接串配置）
- 模式 B（封装）：`PostgreSqlProvider` 新增 `InitializePgVectorAsync()` 方法，用户启动时调用一次

**值转换**：用现有 `[Converter]` 机制
```csharp
public sealed class PgVectorConverter : IValueConverter<ReadOnlyMemory<float>, string>
{
    public string ToProvider(ReadOnlyMemory<float> value)
        => $"[{string.Join(",", value.Span.ToArray())}]";  // PG vector 字面量
    public ReadOnlyMemory<float> FromProvider(string value)
        => ParsePgVectorString(value);
}
```

#### SQLite 方言（sqlite-vec）

**SQL 生成**：
```csharp
// SqlDialect.Sqlite
return $"WHERE {quotedColumn} MATCH {paramName} AND k = {limit} ORDER BY distance";
```

**约束**：sqlite-vec 用虚拟表，DDL 与普通表不同，`[VectorColumn]` 实体在 SQLite 下需生成 `CREATE VIRTUAL TABLE ... USING vec0(...)`。

#### MySQL 方言

**PALORM041 告警**：`Property '{0}' has [VectorColumn] but MySQL has no native vector type; remove the attribute or use PostgreSQL/SQLite.`（编译期阻断）

### 3.4 关键挑战与解

#### 挑战 1：Npgsql 10 的 `UseVector()` 初始化

[事实] pgvector-dotnet 要求 `NpgsqlDataSourceBuilder.UseVector()` 注册向量类型映射。PalORM 用 `new NpgsqlConnection(cs)`，不走 DataSourceBuilder。

**解方案**（三选一）：

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **A：用户预初始化**（推荐） | 文档说明用户在应用启动时调用 `NpgsqlConnection.GlobalSync().RegisterVector()`（待核实 API） | 零 PalORM 改动 | 用户负担 |
| B：Converter 字符串字面量 | 用 `[Converter(typeof(PgVectorStringConverter))]`，把 float[] 转成 `'[0.1,0.2,...]'::vector` 字符串字面量 | 不依赖 UseVector() | 字符串解析慢，无 HNSW 索引 |
| C：PalORM 全局注册 | 在 `PostgreSqlProvider` 静态构造函数调用 `NpgsqlConnection.GlobalRegisterVector()`（如存在） | 透明 | 引入静态可变状态（违反 ADR-E 原则） |

**推荐**：方案 A。与 PalORM 的"无全局可变状态"原则一致。

#### 挑战 2：ReadOnlyMemory<float> 的 AOT 安全性

[事实] `ReadOnlyMemory<float>` 是值类型，源生成器可直接处理。但**写入参数**时 Npgsql 需要 `NpgsqlDbType.Vector`（或 `Unknown` + 显式转换）。

**解决**：
- RowFactory（读）：源生成器生成 `Memory<float>` 的自定义读取代码（`r.GetFieldValue<Memory<float>>(ordinal)`）
- CommandFactory（写）：生成器检测 `[VectorColumn]`，在 binder 中用字符串字面量（`'[0.1,...]'::vector`）参数化

#### 挑战 3：SQLite vec0 虚拟表的迁移

sqlite-vec 的 `CREATE VIRTUAL TABLE ... USING vec0(...)` 与普通建表 DDL 完全不同。

**解决**：MigrationEmitter 检测实体含 `[VectorColumn]` 且方言为 SQLite 时，生成独立的 `vec0` DDL 模板。

## 四、AOT 兼容性

### 4.1 AOT 全链路分析

| 链路环节 | AOT 状态 | 依据 |
|----------|----------|------|
| `[VectorColumn]` 注解解析（编译期） | ✅ | SourceGen ForAttributeWithMetadataName |
| RowFactory 读取 `ReadOnlyMemory<float>` | ✅ | 值类型，无反射 |
| CommandFactory 参数化（字符串字面量） | ✅ | 纯字符串拼接 |
| `OrderByVectorDistance` SQL 生成 | ✅ | 纯字符串拼接，方言分支为常量 |
| `PgVectorConverter.ToProvider/FromProvider` | ✅ | 纯计算，无反射 |

**关键不确定点**：Npgsql 的 `UseVector()` 是否 AOT 安全？

[推断] Npgsql 8.0+ 全面 AOT 兼容（已核实），`UseVector()` 应该也兼容。但 **[待验证]**：需 PoC 实际 `dotnet publish -p:PublishAot=true` 验证 0 警告。

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| `NpgsqlConnection.GlobalRegisterVector()` API 不存在或非 AOT 安全 | 中 | 高 | Phase 1 PoC 必须先验证 API 可用 + AOT 发布成功 |
| pgvector HNSW 索引需 `SET hnsw.ef_search` 才生效 | 中 | 中 | 文档说明；查询前让用户用 `Raw("SET ...")` 设置会话变量 |
| sqlite-vec 跨平台加载（移动端不支持） | 中 | 中 | SQLite 方案降级为可选；PALORM042 告警提示平台限制 |
| 用户对向量搜索需求低 | 高 | 中 | **先 PG 单方言验证需求**，不扩展到 SQLite 直到有反馈 |
