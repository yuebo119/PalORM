# README 性能表模板（性能表-表二，v1.3，2026-11-02 定稿）

> **命名约定（2026-11-02 用户定标）**
>
> - **性能表-表一** = 性能测试生成的全量横评表（`PerfCli report` 输出，报告内编号表一~表七，PerfGate TableGen 生成）。
> - **性能表-表二** = README 性能模块的展示表（本模板）：按方言分表的「操作对照」与「事务对照」，含 🏆 / 💾 双标记（时延最快 / 内存最省）。
> - 两个名称必须带「性能表-」前缀，避免与报告内部的表一~表七编号混淆。
>
> **用途**：以后更新 README 的性能模块一律套用本模板的结构与格式，只替换单元格数值。
>
> **更新步骤**
>
> 1. 跑 `PerfCli crossbench`，或复用最近完整批（`bench/crossbench/results/crossbench-*.json`）。
> 2. 按本模板输出：13 列固定（`操作 | 档 | 🏆 / 💾 | 9 组`）、按方言分表、每格四行（时延 / 时延倍数 / 内存 / 内存倍数）。
> 3. 倍数着色只用于 **PalORM 列**（126 个公式）。GitHub 每页 MathJax 上限约 666 个，全表 1008 个会从第 667 个起显示 `Unable to render expression`。其余组写纯数字，≥2.0 或 ≤0.5 的极端值加粗。着色写法 `$\color{#65a30d}{0.71}$`：GitHub 会剥离 `span style` 与 `font color`，只有 MathJax 的 `\color` 生效（实测渲染为 `mathcolor`）。
> 4. 替换后核对五件事：基准格写纯 `1.00`、🏆 取时延最快组、💾 取内存最省组、着色仅 PalORM 列、着色倍数与模板逐值一致。
>
> **六档颜色**：🟢 `#16a34a`（≤0.70）· 🟩 `#65a30d`（0.71~0.90）· 🔹 `#2563eb`（0.91~0.99）· ⚪ `#6b7280`（1.00）· 🔸 `#d97706`（1.01~1.09）· 🟧 `#ea580c`（1.10~1.29）· 🟥 `#dc2626`（≥1.30）
>
> **参照实例**：本文件下半部分即 2026-11-02 批的成品，数据源 `bench/crossbench/results/crossbench-20261102-110855.json`（9 组 × 三方言 × 两档 × 17 操作，783/783 点）。

## 📊 性能

> **测试环境**：AMD Ryzen 9 8945HX · Windows 10 22H2 · .NET 11 RC2 · SQLite 临时文件库（WAL + 64 MB cache + mmap）· PostgreSQL 18.6 / MySQL 8.4.11 本机容器。
>
> **数据来源**：9 组同批同轮采集，2026-11-02，批次 `crossbench-20261102-110855.json`。9 组为 PalORM / Dapper / Dapper.AOT / linq2db / EF Core / SqlSugar / FreeSql / RepoDb 与 ADO.NET 手写 SQL（基准），各用生态惯用写法。完整报告见 [性能全量报告-2026-11-02.md](性能全量报告-2026-11-02.md)。
