# PalORM 极致性能优化综合方案（终版）

> 日期：2026-11-03
> 依据：src 全部 90 个文件重读、三组实测（驱动级 / 产品级 / 探针级）、全量相等性审计
> 状态：方案定稿，待裁决后执行
> 编写时工作树存在其他会话的活跃写入（见第 1 节），本方案的状态快照以编写时刻为准

## 0. 总体结论

代码已近该架构（micro-ORM + 源生成 + ADO.NET）的性能上限。本轮可收敛的收益分四档，全量门禁只跑一次：

| 档位 | 内容 | 预期 | 状态 |
|---|---|---|---|
| 大 | SQLite 读侧 json_each | 4.9~5.0× 对 Param-IN（探针）；真实基线 PerKey-Reuse 待落地后复测 | 未落地 |
| 中 | MySQL 批宽 | −14.2%~−16.3% | 已落地、已实测、未推送 |
| 小 | MySQL BulkCopy 固定开销 | 每调用约 100-200ns + 若干分配 | 未落地、未实测 |
| 窄 | 动态形状多槽 | 交替形状 −32% | 条件触发（需负载判定） |

另有构建期微优化（48B/查询，4.6%）与两处容量守卫（卫生），列为 Phase 5。

## 3. 工作流与优先级

### Phase 1：已落地项收口（A）

| 序 | 项 | 成本 | 验收 | 依赖 |
|---|---|---|---|---|
| A1 | 全量集成套件 | 5~10 min | 全绿，重点 Bulk 族 | 无 |
| A2 | 外部事务回滚测试 | ~10 min | 回滚后零行（单批原子性唯一直接锁定） | 无 |
| A3 | 回退语句行数断言 | ~15 min | 断言 SQL 形状含 ≤1000 行/语句 | 无 |
| A4 | 工作树测试改动归属确认与提交 | ~5 min | 与外部写入者确认后提交 | 无 |
| A5 | 提交（主仓 12 + `.ai` 状态）+ 推送 | 待授权 | `git status` 清洁；origin/dev 对齐 | A1-A4 |

理由：已落地且已实测，收口成本最低；清洁基线是后续所有 A/B 的前提（G33/B92）。

### Phase 2：SQLite 读侧（B）

| 序 | 项 | 前置 | 验收 |
|---|---|---|---|
| B1 | `GetByKeyManyAsync` API 契约（键类型、返回形态、默认过滤适用性） | 无 | 契约先行的接口签名，供确认 |
| B2 | SQLite 走 json_each（单参数） | B1 | 集成测试：键段完整、抽样值正确、字符串键敌对用例 |
| B3 | 落地后 A/B 复测 | B2 | 基线取 PerKey-Reuse 4.15µs/键；不能直接引用 4.9× |

理由：探针收益最大（4.9~5.0×），范围窄（仅 SQLite）。PG 已有 `= ANY` 数组，MySQL 已有分批。

### Phase 3：MySQL BulkCopy 固定开销（C）

| 序 | 项 | 位置 | 修法 | 预期收益 | 风险 |
|---|---|---|---|---|---|
| C1 | 双次 `EnsureInsertMetadata` | `MySqlProvider.cs:261` + `:451` | 入口取值传入，删 L451 重复 | 每调用省 2 次查找（~50-100ns） | 低 |
| C2 | `quotedTable`/`pkColumns` 未缓存 | `MySqlProvider.cs:454`、`458-459` | 仿 PG `QuotedInsertTargetCache` 建 `(Type)` 缓存 | 省 1 次扫描+Concat、1 次查找、1 次数组 | 低 |
| C3 | `ColumnMappingCache` 键 Join 分配 | `MySqlBulkCopyInserter.cs:60` | 键降为 `(Type)` | 每调用省 1 次 Join（宽表数百 B） | 低 |
| C4 | `ColumnLayout.Build` LINQ | `MySqlBulkCopyInserter.cs:132-141` | 手写单循环或并入 (Type) 缓存 | 省 2-4 次迭代器分配 | 低 |
| C5 | `EntityDataReader` bindRow 闭包 | `EntityDataReader.cs:50` + `MySqlBulkCopyInserter.cs:163` | 直接持有 pool/valuesBinder/entities | 每行省 1 次间接调用 [推断] | 低 |
| C6 | `ColumnOrderValidator` 首行查找 | `ColumnOrderValidator.cs:19` | 调用点传 `info.ColumnNames` | 每查询省 1 次查找 | 低 |

理由：低风险、单文件、同族先例存在；与 Phase 2 无重叠（MySQL 写侧对 SQLite 读侧）。

### Phase 4：动态形状负载（D）

| 序 | 项 | 前置 | 验收 |
|---|---|---|---|
| D1 | 负载判定探针：实际负载是否存在动态 SQL 文本 | 无 | 计数形状数（可选过滤、动态排序列、动态 WHERE 列） |
| D2 | `ReusableQuerySlot` 扩为有界多槽（2~4） | D1 判定为是 | 交替形状分配 −32%（复测）；per-op 会话无泄漏 |
| D3 | `SqlShapeCache` 零子句快速路径（可选） | D2 落地后重估 | PerfHub QueryAll 项 |

多槽风险（必须前置探针）：每会话多保留 2~3 个 `DbCommand`；per-op 会话形态下多形状各自晋升可能绕过阈值 3 的泄漏防线。先验证门禁语义再实施。

### Phase 5：构建期微优化与容量守卫（E）

| 序 | 项 | 前置 | 验收 |
|---|---|---|---|
| E1 | BuildSql 命中路径免物化子句数组 | 先复测 FirstAsync 路径占比 | 若 ≥5% 则做；实现走链哈希 + 全值核对的折中方案 |
| E2 | `OrderByClauseText` 加容量上限 | 无 | 满员处理（拒写或满清），照抄 `SqlShapeCache` 1024 纪律 |
| E3 | `PartialUpdateSqlCache` 加容量上限 | 无 | 同上 |

理由：E1 收益 4.6% 低于线，E2/E3 属卫生（动态 CTE 名与 2^N 子集的无界增长）。放最后，不阻塞主收益。

### Phase 6：验证与门禁（F）

| 序 | 项 | 时机 |
|---|---|---|
| F1 | 每项改动 BDN/PerfHub 交替 A/B（≥3 批，双指标） | 每项落地后 |
| F2 | 全量 `PerfCli full` + `PerfGate` | Phase 2-5 全部落地后（一次覆盖） |
| F3 | 结果库 `PerfCli report` 重建 | F2 后 |

## 5. 相等性审计结论（值相等确认）

### 5.1 哈希相等替代值相等：两处

| 位置 | 机制 | 是否值核对 | 结论 |
|---|---|---|---|
| `SqlShapeCache.Buckets`（SqlShapeCache.cs:31） | 哈希只选桶，命中后 `Matches` 逐条核对 `ShapeFields` + `SqlSequence` + `KindSequence` + `QualifySequence`（:163） | 是 | 安全，碰撞只落未命中重建 |
| `CircuitBreakerRegistry.Key.ConnectionStringFingerprint`（CircuitBreakerRegistry.cs:59-63） | 连接串替换为 64 位 FNV-1a 指纹（:48-57） | 否 | 已登记取舍：碰撞概率 2^-64，后果是两个不同连接串共享熔断状态 |

### 5.2 全量相等性决策表（运行时）

| 类别 | 结构 | 键 | 相等机制 | 确认 |
|---|---|---|---|---|

| 值相等键 | `DataSessionCache.*`（13 个字典） | `(Type, Dialect[, bool, bool])` 等元组 | `ConcurrentDictionary` 默认值相等 | 安全 |
| 值相等键 | `FormattableSqlFormatter.ShapeCache` | `(string, int, int, Dialect)` | 值相等 | 安全 |
| 值相等键 | `PostgreSqlExtensions.JsonFormatCache` | 列名 | 值相等 | 安全 |
| 值相等键 | `MySqlBulkCopyInserter.ColumnMappingCache` | `(QuotedTable, string.Join('\u0001', columns))` | 值相等（连接串编码） | 安全（见 5.3） |

### 5.3 身份编码确认项

| 项 | 位置 | 机制 | 结论 |
|---|---|---|---|
| `\u0001` 连接键 | MySqlBulkCopyInserter.cs:60 | 列名用 `\u0001` 连接后作键 | 单射性依赖控制字符拒绝。生成器 PALORM043（PalORMAnalyzer.cs:1238）与运行时 `IdentifierSafety.ThrowIfUnsafe`（IdentifierSafety.cs:30）双重拒绝 C0/C1/DEL，`\u0001` 在拒绝范围内，安全 |
| 逗号连接索引键 | DataSession.PartialUpdate.cs:152 | `SortedSet<int>` 逗号连接 | 非负整数有序连接是单射，安全 |
| 连接串元组键 | `MySqlProvider.RewrittenConnectionStringCache`、`PostgreSqlProvider` 同名缓存 | 元组含连接串原文 | 值相等，无编码，安全 |

### 5.4 无容量上限的缓存（相邻风险）

| 缓存 | 键空间 | 注释声称 | 实际情况 | 建议 |
|---|---|---|---|---|
| `QueryBuilderShared.OrderByClauseText`（QueryBuilder.cs:1859） | `(Type, Dialect, SourceName, PropertyName, Descending, Continue, IsGroupBy)` | 「键成分不含用户值」 | 不成立：`SourceName = _cteName ?? _tableName`（:1071），`_cteName` 由 `With(cteName, ...)` 用户传入 | 加容量上限 |
| `DataSessionCache.PartialUpdateSqlCache`（DataSessionCache.cs:76） | `(Type, Dialect, Columns, Tenant)` | 「列子集数量有限」 | 每类型 2^N 子集（N = 可更新列数），无淘汰 | 加容量上限 |
| `QueryBuilderShared.ClauseText`（QueryBuilder.cs:1867） | `(Dialect, Kind, Prefix, Sql, Parenthesized)` | 未声称 | `Sql` 受 `FormattableSqlFormatter` 4096 上限约束，有界 | 不动 |

### 5.5 另一处已登记残余

`SqlSlots<T>` 静态槽不随 `RestoreStateForTesting` 失效（DataSessionCache.cs:81-82 注释，P2-1 残余）。仅测试路径可达，产品注册表单调（`Register` 拒绝重复类型）。

## 6. 暂缓项（合并去重，附理由）

| 项 | 理由 | 来源 |
|---|---|---|
| 批量路径同步 I/O | 驱动级实测收益为零 | 会话 A |
| BuildSql 免物化（未复测前） | 4.6%，低于 5% 线 | 会话 A |
| 参数两趟循环合并 | 未测，构建期小成本 | 会话 A |
| EntityDataReader 逐列类型化读取 | 已证伪（驱动走 `GetValues(object[])`） | 会话 B |
| MySQL 读侧批量 | 无探针数据，PG/MySQL 已有管道与 `= ANY` | 会话 B |
| per-op 会话命令复用 | 阈值 3 是防泄漏设计约束 | 代码事实 |
| DbBatch 轮次 100→200 | 低于 5% 线 | 会话 B |
| 5.2 能力化（`IDbProvider` static virtual） | 第三 Provider 出现再升 | 会话 B |
| `CircuitBreakerRegistry` 指纹改原文键 | 会驻留凭据（违反 P3-8）；加二级比较复杂度远超 2^-64 收益 | 代码注释 |
| 行工厂去委托 | 收益 <1ns/行，注册表是 `Dictionary<Type, object>`，结构改动大 | 代码事实 |

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| SQLite json_each 读侧语义与删除侧不一致（字符串键、NULL、类型推断） | 中 | 复用删除侧 `BuildJsonKeyArrayText` 真源；字符串键敌对用例锁定 |
| `GetByKeyManyAsync` 契约与默认过滤冲突 | 中 | 契约先行；默认过滤适用性与 QueryAsync 对齐 |
| 多槽改造绕过阈值 3 泄漏防线 | 高 | 实施前探针验证门禁语义；每会话命令数设上限 |
| E1 降级为哈希核对会改变碰撞正确性保证 | 中 | 若做，保留链哈希 + 全值核对的折中（链上逐节点比较），不复用 `Matches` 的数组路径 |

| 动态形状负载判定为不存在 | 低 | D1 探针后直接跳过 Phase 4 |
| 工作树有活跃外部写入者 | 中 | 提交类动作先确认归属；只暂存本方案相关文件 |
