## 2. 查询构建与单行查询

数据源：`bench/results/benchmarks-20261031-213532.json`。

| 方法 | 均值 | 分配 | 相对 GetAsync |
| --- | ---: | ---: | ---: |
| From_Only | 34.23 ns | 0 B | - |
| From_Where | 84.90 ns | 208 B | - |
| From_Where_OrderBy_Expression | 363.86 ns | 1040 B | - |
| GetAsync_One | 1248.88 ns | 712 B | 1.00 |
| ToList_Where | 1738.19 ns | 1352 B | 1.39 |
| ToList_Where_OrderBy | 2375.72 ns | 2536 B | 1.90 |
| PerOp_GetAsync | 26831.52 ns | 3688 B | - |
| Pooled_GetAsync | 7079.13 ns | 2032 B | 0.26 |

读法：

- `From<T>()` 在会话预热后零分配，34 ns 是纯结构构造。
- 单个 `Where` 增加 208 B 与 51 ns，单个 `OrderBy(表达式)` 再增加 832 B 与 279 ns。
- `ToList(where)` 比 `GetAsync` 多 490 ns 与 640 B，这是 LINQ 管线的固定差。
- `ToList(where+order)` 比 `GetAsync` 多 1127 ns 与 1824 B，其中 OrderBy 构建约占 832 B。
- 按操作会话比池化租还多 19752 ns 与 1656 B，池化是本轮最大的单点。

## 3. 原始 ADO 同步与异步叶子

数据源：`C:\temp\palorm-probe` 的 `probe3.cs`、`probe6.cs`（临时探针，不入仓库）。

| 操作 | 同步 | 异步 | 差值 |
| --- | ---: | ---: | ---: |
| 打开 reader（1 行） | 376 B / 1009 ns | 520 B / 1156 ns | +144 B / +147 ns |
| 标量 | 400 B / 1237 ns | 472 B / 1278 ns | +72 B / +41 ns |
| 非查询（影响 0/1 行） | 152 B / 1138 ns | 152 B / 1056 ns | 0 / 0 |
| 逐行读（1000 行） | 274 ns/行 | 276 ns/行 | 0 / +2.4 ns |
| 命令复用（2000 行读） | 323093 ns | 342950 ns（每次新建命令） | +6% / +312 B |

读法：

- 逐行 `ReadAsync` 返回缓存的 `ADP.TrueTask/FalseTask`，没有分配；逐行同步叶子没有收益。
- `ExecuteNonQueryAsync` 在影响行数 0/1 时命中 `Task.FromResult` 缓存，没有分配；按主键逐行写不需要改同步叶子。
- 只有每次查询的 reader 打开与标量存在 72 到 144 B 的固定分配差，价值在“每查询”，不在“每行”。
- 命令复用在 2000 行读上约 6%，不是 30% 级的差异。

## 5. 实施后复测（2026-10-31 晚，M2/M3/M4 已落地）

数据源：`bench/results/benchmarks-20261031-*.json`，同一 `LinqBuildBenchmarks`、同一 job 配置。

| 方法 | 基线 | 实施后 | 变化 |
| --- | ---: | ---: | --- |
| From_Only | 34.23 ns / 0 B | 33.24 ns / 0 B | 持平 |
| From_Where | 84.90 ns / 208 B | 87.61 ns / 208 B | 持平 |
| From_Where_OrderBy_Expression | 363.86 ns / 1040 B | 333.16 ns / 808 B | 分配 −22% |
| From_Where_OrderBy_String | 未测 | 148.52 ns / 264 B | 较表达式 −55% 时间、−67% 分配 |
| GetAsync_One | 1248.88 ns / 712 B | 1142.20 ns / 712 B | 分配持平 |
| ToList_Where | 1738.19 ns / 1352 B | 1540.89 ns / 1208 B | 时间 −11.3%，分配 −10.6% |
| ToList_Where_OrderBy | 2375.72 ns / 2536 B | 2111.71 ns / 2088 B | 时间 −11.1%，分配 −17.7% |
| Compiled_ToList_Where | 未测 | 1192.67 ns / 848 B | 较 Fluent ToList_Where 时间 −22.6%，分配 −29.8% |
| PerOp_GetAsync | 26831.52 ns / 3688 B | 26448.50 ns / 3688 B | 持平 |
| Pooled_GetAsync | 7079.13 ns / 2032 B | 6553.65 ns / 2032 B | 持平或更优 |

判读：

- M2 目标达成：`ToList(where)` 1541 ns / 1208 B 低于 ≤1600 ns / ≤1100 B 的时延线，分配略高于线（1208 vs 1100），但相对基线降 10.6%，按分配优先口径记为达标偏差，后续不追单项。
- M2 `ToList(where+order)` 2112 ns / 2088 B 低于 ≤2100 ns 时延线，分配高于 ≤1900 B 线 188 B，记为偏差；字符串重载本身已把单条 OrderBy 从 808 B 降到 264 B，剩余为 FormattableString/管线固有。
- M3 决策门通过：编译查询较优化后的 Fluent 路径时间 −22.6%、分配 −29.8%，高于 10% 门槛，保留公共 API。
- 池化会话仍是最大单点：26448 ns → 6554 ns（−75%），3688 B → 2032 B（−45%）。
