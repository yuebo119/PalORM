# PalORM 测试体系优化方案（2026-11-01）

> 前置阅读：`docs/测试体系增强方案-2026-10-31.md`（已实施 35 任务）、`docs/一致性测试总报告-2026-10-29.md`、`.ai/test/prompt.md`。
> 本方案回答一个问题：在已有 1514 个 `[Test]`、四层一致性防线、四路 AOT 的基础上，下一步做什么能把"绿灯的可信度"提到与规模相称。
> 结论：不新建测试体系，做三件事——让三条未通电的自动化真正运行、把地板与守卫改成能失败的形状、补齐第三方言与消费面的判别力。

## 六、关键设计决策

### 6.1 调度错位的修法：workflow 在 main，代码检出 dev

GitHub 只从默认分支注册 schedule。全量合并 dev 到 main 风险过大，最小解是：workflow 文件留在 main，checkout 显式 `ref: dev`。这样调度、代码、修复三者都在同一条线上，且不需要每次改 workflow 都发版。

代价：schedule 运行的是未发布代码，失败不阻塞发布。处置是 job 失败时开 issue 并打 `test-infra` 标签，与发布解耦。

### 6.2 变异测试：修路径优先，回放兜底

2026-10-03 起的失败根因是 main 的 `stryker-config.json` 指向 `PalORM.slnx`，在干净检出上 `bench/PalORM.Benchmarks` 无法还原 BDN（CS0246）。dev 已改 `PalORM.mutation.slnx`，但未合 main。

修法：基础设施 cherry-pick。若上游 MTP runner 仍返回 exit 3，则 Stryker 降级为 advisory，由 11 条回放规则承担阻断职责，并每月评估一次是否恢复。

### 6.3 地板：从"只降不升"改为"自收紧"

现行规则"新增用例无需上调地板"导致地板相对实测单调衰减，三个月从 -10% 衰减到 -50%。

新规则两条同时生效：

1. `passed >= floor`（防删除）。
2. `floor >= 0.95 * passed`（防衰减），失败时输出建议地板值。

第二条会带来"每次加测试都要改基线"的摩擦。缓解：由 CI 在月度第一个工作日自动提交地板更新，人工只审 diff。

### 6.4 T1 机械化：用 diff 覆盖率，不做方法-测试映射

"每个新公共方法必须有测试"的机械映射会产生大量无判别力断言，且无法覆盖私有路径修改。

改用业界通行的 diff 覆盖率：只统计本次改动涉及的行（`git diff -U0` 的行号区间），要求 80% 命中。门禁命名为 `T1-diff`，与 T1 铁律一一对应，白名单只允许三类：纯注释、`#if` 条件编译块、生成物 `.g.cs`。

### 6.5 分支地板：停止把 block 叫 branch

`dotnet-coverage` 无独立 branch 属性，现行脚本用 `block_coverage` 代理。这不是错误，但名称会误导读者认为分支已被覆盖。修法是改名并在输出中同时给 block 与条件表达式计数两列，地板只锁 block。

## 七、执行纪律

1. 每个新增门禁必须配一条注入探针，进 `verify-ai-system --probes`；探针不红的门禁不得上线（对应 V17 判据）。
2. 每修一个产品缺陷，同提交加一条回放规则与 `Catchable-By:` trailer（沿用 2026-10-30 随修随加纪律）。
3. G0 全部完成后才开 G1；G1 的覆盖率提升依赖 G0 的门禁能正确报红。
4. 任何阈值调整必须先跑"调整前/调整后"两批，确认被放过的项全是边际值（对应 B202 纪律）。
5. 每周五巡检 `gh run list --limit 20` 全量 workflow 状态，红项当周立案；连续两周红的 job 升级为 P0。

## 八、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| cherry-pick 到 main 后 workflow 与仓库状态不匹配 | 中 | 调度持续红 | 先在 dev 用 `workflow_dispatch` 跑通，再 cherry-pick |
| diff 覆盖率误伤大文件重排 | 中 | 开发者绕过 | 只统计改动行；重排提交单独标注 `[no-diff-cover]` 并由人工审 |
| 地板收紧立即红 | 高 | 阻塞合并 | 先输出报告一周不阻断，再转门禁 |
| 驱动矩阵暴露大量既有不兼容 | 中 | 夜间长期红 | advisory 两周，逐项登记后转门禁 |
| Windows lane 不稳定 | 中 | 噪声 | 只跑 SQLite，超时 20 分钟，失败自动重跑一次 |
| Postgres 覆盖率提升慢 | 中 | 目标落空 | 以方法清单驱动，按四个未覆盖方法逐个闭环 |
