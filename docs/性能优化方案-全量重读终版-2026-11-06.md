## 0. 结论

库已无数量级空间。SQLite 点查 0.901×、事务写 0.94~0.98×、批量 0.93~1.03× 对齐或优于手写 ADO；剩余差是纳秒税与批间摆带值，不是结构性缺陷。

最终只保留一个实质项 F1（SQLite 批量写补同步叶子分流），三个低风险机械项 F2a/F2b/F2c，两个只出结论不预写修复的探针 F3a/F3b。其余一律关闭。

F1 必须先过 A/B 探针正收益才动代码，证伪即丢弃。

### 1.2 已撤回与已证伪项

1. 撤回「LINQ 管线首行列序校验冗余」：`QueryBuilderExtensions.cs:188-193` 的 `ExecuteListCoreAsync` 本就不传 `onFirstRow`，校验只在 raw SQL 入口（`DataSession.Query.cs:502`、`:576-579`）。上一轮基于误读。
2. 构建路径 CD 查找点是 5 处，不是 3 处：补 `QualifiedSelectColumnsCache`（`QueryBuilder.cs:1403`）与条件性注册表点（`DataSession.Crud.cs:52`，稳态被 `EntityInfoCache` 短路）。
3. 读路径门禁是三把锁：`EnsureAvailable`（`:761`）、`EnterReadOnly`（`:373`）、`ExitReadOnly`（`:406`）。
4. `SessionOperationState` 含 3 个 AsyncLocal（`:23`、`:24`、`:330`）。`DbOptions` 构造是 bench 夹具侧，不是产品会话税。
5. B2-1 探针（`tmp/bulkprobe/run.log`）证伪了「EntityDataReader + 参数池中介层」假设：Phase 3 用逐字节复刻的直读 reader 仍差 368.1ns/行（1.040），说明差距不来自读取器中价。

## 2. 最终方案

### F1（最高优先，唯一实质项）SQLite 批量写路径补同步叶子分流

- 锚点：`RowPreparedBulkInsert.cs:185-189`、`:195-201`（行循环硬编码 `await cmd.ExecuteNonQueryAsync`）；`DataSession_Bulk.cs:1131`（`ExecuteBulkUpdatePooledAsync` 逐条分支同源缺口）。
- 同构先例：`DataSession.cs:1768-1777`（`ExecuteRowsCoreAsync` 的 `PreferSynchronousIo` 分流）、`SqliteProvider.cs:133`（声明 true）。
- 改法：`RowPreparedBulkInsert.ExecuteAsync` 加 internal 重载收 `bool syncIo`，`SqliteProvider.BulkInsertAsync` 传 `TProvider.PreferSynchronousIo`；行循环两分支（池化/legacy）各分流，`ct.ThrowIfCancellationRequested()` 前置；`BulkContext` 公共面不动。`DataSession_Bulk.cs:1131` 同形态，仅在 SQLite 逐条分支生效（`SupportsBatchedPooledUpdate :1154-1155` 已排除 MySQL/PG）。
- 目标：收窄 SQLite BulkInsert +46.0ns/行、UpsertBatch +35.3ns/行、PooledBulkInsert +47.3ns/行 中可归因部分。不承诺反超。
- 反驳：同步执行取消粒度变粗（单行约 2µs，与 DataSession 既有形态一致）；runtime-async=on 下外壳成本可能已很低，若同步反而更慢，S3 反向验证后丢弃，不留代码；BulkUpdate 0.982× 已优，改它只扩大优势，须单独 A/B 确认不退化。

### F2a `QualifiedSelectColumnsCache` 迁闭式泛型静态槽

- 锚点：`QueryBuilder.cs:1400-1407`，BuildSql 命中必走的一次 `(Type, SqlDialect)` CD 读。
- 改法：迁 `SqlSlots<T>` 同型槽（先例 `DataSession.Crud.cs:1278`），`DataSessionCache.ClearForTesting` 同步清理。
- 方向确定、行为零变化，纯机械降本。

### F2b `DbOptions.Validate` 加 `_validated` 标志

- 锚点：`DbOptions.cs:185`、`DataSession.cs:180`。record init-only 不可变，通过即置位，`With*` 新实例归零。
- 省每 `CreateAsync` 一次约 24 项校验链。非法配置仍抛。

### F2c `SessionOperationState.EnsureAvailable` 免锁快路径

- 锚点：`SessionOperationState.cs:761`。先 `Volatile.Read(_state)==0` 直接返回，失败回落锁。
- `EnterReadOnly` / `ExitReadOnly` 的 CAS 化与 `Exit` 无锁化不做（并发协议复杂，收益与风险不成比例）。

### F3a / F3b 未归因差探针（只出结论，不预写修复）

- F3a SQLite TenantGetAll +1.03ms/2000 行：候选假设（容量启发首查 16 走溢出路径、BenchTenantPost 7 列含 OwnedJson、租户参数绑定）全标 [猜测]，先逐段计时探针。
- F3b MySQL GetByKey +19.2µs：候选为 per-op 会话构造税、命令新建、文本协议解析；池化臂 0.821× 已快，反证构造税为主嫌 [推断]。

## 3. 关闭项（不做清单）

| 项 | 关闭理由 |
|---|---|
| B2-1 MySQL PooledBulkInsert 深挖 | 探针证伪为摆带值，无稳定税 |
| MySQL 同步命令 opt-in | 网络方言 0.1% 级收益，同步阻塞语义有害 |
| `ExecuteListCoreAsync` 同值守卫 | SQLite 可能负收益，A/B 裁定后再议 |
| `FormatCached` / `GetClauseText` 短格式旁路 | 省 CD 读但多串分配，净符号未定 |
| 批量族 B1-1 / B1-2 | 分配面小收益，优先级低于 F1 |
| `Exit` 无锁化、`EnterReadOnly` CAS 化 | 并发协议复杂 |
| 删 raw SQL 列序校验 | 已撤回（基于误读），ADR-A 契约保留 |
| 已裁决勿重开的七项批量形态 | DbBatch 跨轮、短批池化、ODKU 1000、UNNEST 20000、CASE WHEN SQLite、VALUES() 双形态、32766 大值 |
| 进程级命令缓存、RowFactory 形态变动 | DbCommand 绑连接；已类型化直读零装箱 |

## 4. 验收口径

- 每项任务 completed 的唯一依据是验收命令通过，不是代码写完。
- F1 是唯一可能改变热路径行为的项：必须 A/B 探针正收益才动，改完跑 PerfHub SQLite 四项（BulkInsert / UpsertBatch / BulkUpdate / PooledBulkInsert）A/B，再做 S3 反向验证（移除因子退化回基线）。
- F2a 要求生成物快照零变化；F2b 要求非法配置仍抛；F2c 要求并发混合臂与 `ArchitectureInvariantTests` 锁协议用例全绿。
- 全量门禁：`dotnet build PalORM.ci.slnf -c Debug` 0 警告 0 错误、Core 与 Integration 全绿、pre-commit 八段、`git status` 清洁。
- 性能数字口径：同批九组、两遍反序 Average、比值分母为同批 ADO 基准；跨机绝对值不可比。比值只作定性，B100 纪律。

## 5. 风险

主要风险是 F1 的同步化在 runtime-async=on 下无收益甚至负收益。缓解：A/B 探针先行、S3 反向验证兜底、证伪即丢弃。其余 F2 三项是纯机械降本，行为零变化；F3 两项只出探针结论，不进产品代码。
