## 一、结论摘要

PalORM 已把每操作固定成本压到结构性下限：注册表单次 Volatile.Read 快照、struct QueryBuilder、编译期 SQL 字面量、SqlShapeCache 形状缓存、ParameterNameCache 零分配取名、PL-2 惰性晋升命令池、租约 TCS 惰性化、O1 至 O4 批量优化均已落地。本次逐项复核后，剩余可抢收益集中在三个方向：

**方向一：每操作固定成本（纳秒到数百字节级，全部 API 共享）**

| 项 | 现状（本次代码事实） | 可抢 |
|---|---|---|
| 直查族格式化未走形状缓存 | `DataSession.cs:922-923` 调 `FormattableSqlFormatter.Format`（无缓存），QueryBuilder 路径走 `FormatCached` | 每次直查省一遍复合格式扫描 + 输出串复用（约 40B+，[实测] 注释口径） |
| Count/聚合标量走 async lambda 包装 | `DataSession.Query.cs:48-50` 与 `142-144`：`async token => await cmd.ExecuteScalarAsync(token)` | 约 208B/次（P2-1 同型已为写路径做过，注释实测 208B） |
| 弹性每尝试 linked CTS | `Resilience.cs:108-109`：无条件 `CreateLinkedTokenSource` + `CancelAfter` | 168B/尝试中 linked 注册开销的一部分；无限超时配置可全省 |
| 熔断成功路径无条件加锁 | `CircuitBreaker.cs:112-129`：`RecordSuccess` 恒进 `lock`，即使已处于全零状态 | 默认配置下每次成功操作省一次 Monitor 进出 + 5 字段写 |
| 缓存命中一次墙钟读取 | `CacheStore.cs:205-206`：`DateTime.UtcNow` | 每次命中省一次墙钟调用，消除回拨超期 |
| CrudMetadata 按值传递 | `CrudMetadata.cs:141` 起约 15 字段 struct（约 120B），消费链复制数次 | 数次结构体复制（JIT 依赖，需实测） |

合计约 400 至 600B/操作。注意：PerfHub 的 PalORM 臂用默认配置（非直通），弹性三项在其上可见；BDN 直通配置下不可见。

**方向二：批量与大 N 场景（KB 到数十 MB 级，本次最大金矿）**

1. BulkMerge 默认键分支每行一次 `SaveCoreAsync`（`DataSession_Bulk.cs:893-904`）：20000 行 20000 次往返，改批量 INSERT + ID 回填后收敛到 1 至 8 次。
2. BulkUpdate 逐条 DbBatch 路径（`DataSession_Bulk.cs:426-476`，`BindIntoBatchCommand:498-512`）：每行一条 BatchCommand、每参数一个新建对象，20000 行约 42 万参数对象。
3. BulkDelete 无参数池（`DataSession_Bulk.cs:115-127`）：每 key 一个 `CreateParameter` + 装箱，20000 key 约 2 至 5MB。
4. MySQL local_infile 探测缓存键是连接对象（`MySqlProvider.cs:253`）：每操作一会话形态下每次 BulkInsert 付一次 `SHOW VARIABLES` 往返。

**方向三：生成器与 Provider 接缝（每行每列级）**

INSERT 参数池每行每列重复写 DbType（`CommandFactoryEmitter.cs:447-448`，[实测] 注释 31ns 对 13ns）；PG COPY 路径每次调用为首行采样建一整组参数对象（`PostgreSqlProvider.cs:346-358`）；MySQL BulkCopy 每批重建池与命令（`MySqlBulkCopyInserter.cs:112-141`）。这些是"编译期已知但运行时重算"的集中地。

## 二、全局地基：七层共享成本与优化位点

### 2.1 会话创建（CreateAsync / PreWarmAsync）

- 路径：`DataSession.cs:113-189`（ResolveConnectionString → CreateConnection → OpenAsync + 链接 CTS → 初始化钩子 → SessionSetupSql → 构造）；重试循环含退避。
- 每会话固定成本：1 个连接对象 + 驱动侧解析/建连（SQLite 含一次 PRAGMA 往返）+ 1 个 `ResilienceExecutor` + 拦截器 List + 1 个 `SessionOperationState`（含 2 个 AsyncLocal + 1 个 Lock）。
- 可抢项：SQLite 连接串解析缓存（C3）；MySQL/PG 连接串改写缓存已存在，未命中路径的 Keys 线性扫描可合并（C14）。`SessionOperationState` 每次创建 2 个 AsyncLocal 是结构必需（跨 async 流归属判定）。
- PreWarmAsync 逐条建连归还，语义上无优化空间（动作本身即预热）；SQLite 直接返回。

### 2.2 操作租约（SessionOperationState）

- `Enter`（`:50-96`）：lock + 最多 6 项检查 + AsyncLocal 写（首次/新异步流约 300B EC 拷贝；v4.6 用 `this` 复用使同流第二次值相等短路）。
- `Exit`（`:688-707`）：lock + 字段清空，v4.5 起不写 AsyncLocal。
- `EnterReadOnly`（`:137-165`）：锁内分支，并行读作用域外退化 `Enter`。
- `GetActiveTransaction`（`:468-495`）：每次 lock + IsTransactionAlive；被 `CreateCommand`、`QueryBuilder.GetActiveTransaction`、`TryAcquire*Command` 等每次操作调用 1 至 3 次。
- 结论：[事实] 已到形态极限（两轮专项优化 v4.5/v4.6）。可微抢：单操作内 `GetActiveTransaction` 结果不漂移（门禁保证），可在一处取快照下传，省次操作 1 至 2 次无竞争 lock（纳秒级，列为 D 类观察项，不单独立项）。

### 2.3 弹性管线（Resilience / CircuitBreaker）

- `IsPassThrough = _maxRetries == 0 && !_circuitBreaker.IsEnabled`（`Resilience.cs:21`）。Testing 预设与负载器材为直通（零参与）；**默认 DbOptions 非直通**，只读查询与单行写每次进执行器。
- 每查询固定成本 [实测]：272B = 168B（每尝试 linked CTS + CancelAfter 定时器）+ 56B（调用点委托）+ 48B（执行器机械 + 状态机），与行数无关（`QueryBuilderExtensions.cs:184-196` 注记三项独立测量）。
- `CircuitBreaker.Enter`（`:60-92`）：Closed 态零锁（volatile 镜像快路径）；`RecordSuccess`（`:112-129`）**无条件 lock**；`RecordFinalFailure` 无条件 lock（失败路径，可接受）。
- 可抢项见 A3（CTS 单构化）、A4（成功短路）。
- [证伪] 只读内核 struct 化（step10，-61B < 200B 线）与调用点委托消除（需手写 awaiter 重构外层，T5 级深水区，104B 级收益）不得重开。

### 2.4 命令生命周期（CreateCommand → Dispose）

- `DataSession.CreateCommand`（`:768-778`）：`_conn.CreateCommand()` + `GetActiveTransaction()`（lock）+ timeout 写。每查询一次（QueryBuilder 族、直查族）；PL-2 惰性晋升覆盖单行 Insert/Update/GetByKey（第 3 次调用起复用，`TryAcquireInsertCommand:200-240` 等）。
- 释放侧：`await using DbCommand` → 驱动 Dispose。PL-2 注释 [实测]：命令的新建与释放是大头（只池化参数回收 12%，命令 + 参数回收 39%）。
- 可抢项：A9（复用泛化到 QueryBuilder 读查询族）。
- [证伪] 无条件命令缓存（会让"每操作一会话"泄漏未释放命令，实测并发混合慢 4.84×），必须维持惰性晋升阈值 3。

### 2.5 参数绑定

- 池路径（生成器 `BindInsertValues` 等）：`parameters[offset+i].DbType = ...; .Value = (object)值`，每行每值类型列一次装箱 + 一次 DbType setter。
- 新建路径（`BindInsert` 等）：每参数 `cmd.CreateParameter()` + Add。
- 直查族：`BindFormattableParameters`（`DataSession.cs:926-934`）每参数 `TProvider.CreateParameter` + Add。
- 可抢项：B1（BulkDelete 池）、B21（INSERT 池 DbType 一次性初始化）、C1（PG CreateParameter 频率重排）。
- 不可优化面：池路径每格装箱（除 PG COPY 定型路径 `CopyWriteRow` 已归零，`IBinaryRowSink.cs:4-7` [实测] S1Row 104B/行）。

### 2.6 SQL 构建与缓存

- `BuildSql`（`QueryBuilder.cs:804-881`）：形状哈希现算（O(子句) 次 `HashCode.Combine`）→ `SqlShapeCache.FindMatch`（1 次 int 桶查 + O(子句) 值核对，零分配）→ 命中即复用同一 string 实例；未命中 VSB 构建 + `Add`。
- 全列清单走 `(Type, Dialect)` 缓存（`GetQualifiedColumnList:929-936`）；直查族 SQL 走 `DataSessionCache` 多处 `(Type, Dialect, ...)` 缓存。
- 格式化：QueryBuilder 路径 `FormatCached`（命中零分配、string 实例复用）；**直查路径 `Format` 无缓存**（A1）。
- LIMIT/OFFSET：值参数化（SHAPE-010 根解）；First/Single 族在 SQLite 上字面量 `LIMIT 1/2`（[实测] 5.658µs 对参数化 13.557µs，`QueryBuilder.cs:1160-1162`）。

### 2.7 物化与读取

- RowFactory（生成物）：`static readonly Func<DbDataReader,T>`，编译期 ordinal 字面量，每行 1 实体 + 每列 1 次（非空）/ 2 次（可空）reader 虚调用；`#nullable disable` 引用列多一次 IsDBNull + 常量比较。
- 消费侧每行一次委托 invoke（类型擦除注册表固有）；`ColumnOrderValidator` 仅首行（直查）/每结果集（GridReader）执行。
- 不可优化面：reader 虚调用与委托 invoke（ADO.NET 接口 + 方言无关生成物，`RowFactoryEmitter.cs:167-172` 记录 byte[] Span 化尝试被驱动兼容性回滚）。

### 2.8 释放与收口

- 命令/reader Dispose、连接 Close/Dispose、复用命令统一释放（`DisposeReusableCrudCommandsAsync`）、读连接与并行读池释放。
- 每事务提交：`TransactionCleanup.CommitWithTimeoutAsync:135-162` 默认 30s 超时 → linked CTS + 定时器（A 类可抢，D6）。

**F2：`LiveHeapAfterBytes` 指标口径判别力（基准改进候选）**

### 预登记探针轮（F1 判定 + A9 立项 + B3 两方言结论 + B2 预登记，2026-10-01）

**F1（会话构造减重）：负结果，读码+核算阶段淘汰**
- 标定（`.ai/perf-probe/SessionCtorDiag.cs`，经 Escape 逃逸出口修正 .NET 11 对象栈分配的测量污染——首版 new object() 11B、实例方法组 0B 即此症）：`AsyncLocal<T>` 24B/个、`Lock` 40B、实例方法组委托 56B、static lambda 0B、`CircuitBreaker(5,30s)` 120B。
- 可减项核算：AsyncLocal 惰性化净省仅 2×24=48B（`_currentOperationOwner` 为 Enter 必用不可省；`_currentTransactionOwner`/`_readLeaseDepth` 非事务/非并行读会话可免）；CircuitBreaker 120B 在默认配置（阈值 5）必须建（会话级状态，惰性化对每操作一会话无收益）；实例方法组委托 112B 为实例绑定结构性成本；backoff 闭包在 step11 P1 证伪域。
- **判定：可减上界 72B（3×AsyncLocal 全免的数学极限）< 200B T5d 线 → 淘汰，勿重开**。核算表与标定数据固化在 SessionCtorDiag.cs。

**A9（QueryBuilder 命令复用泛化）：立项（收益上限探针完成）**
- 直驱 SQLite 两臂对比（`.ai/perf-probe/KeyLookupCommandDiag.cs`，20000 次采样、交替双跑排除顺序效应）：臂 A（每查询新建命令+参数+Dispose）**1144 B/op / 3.97µs**；臂 B（命令+参数建一次、循环改值重执行）**640 B/op / 1.40µs**。**上限 = -504B/op、-2.57µs（时延 -65%）**，双跑稳定。
- 判定：远超 200B 线，**立项**。实施设计要点（留实施轮）：形状缓存命中的 SQL 引用相等作复用键、PL-2 惰性晋升（阈值 3）防"每操作一会话"泄漏、参数值重建语义、真库三方言验证。

**B3（DbBatch 参数/命令跨轮复用）：两方言探针结论——PG 不可行、MySQL 可行，降级**
- PG（Npgsql 10.0.3，`PgDbBatchReuseDiag.cs`，每形态独立连接）：①同 batch 改值二次执行抛 `Missing type info or binding info`（首轮成功、二次失败——BatchCommand 执行消耗参数内部状态）；②跨 batch 复用命令对象同样失败；③跨命令共享参数对象被拒（`The parameter already belongs to a collection`，确认"每命令独立集合"约束）。→ **PG 侧 B3 前提否定**。
- MySQL（MySqlConnector 2.6.2，`MyDbBatchReuseDiag.cs`）：①②均成功且四行结果值全部正确（1→10、11→110、2→20、22→220）→ **MySQL 侧支持复用**。
- 判定：B3 降级为"MySQL-only、窄场景（乐观锁/软删实体的逐条池化 DbBatch 路径）"——需方言分叉实现，收益/复杂度比显著下降，**不推荐优先**；探针结论已固化，防未来重开时重复探针。

**B2（BulkMerge 默认键批量 INSERT + 回填）：预登记（原型留专轮）**
- 现状（代码事实）：默认键实体走逐行 `SaveCoreAsync`（`BulkMergeAsync`，DataSession_Bulk.cs:893-904），20000 行 = 20000 次往返。
- 目标：多值 INSERT + ID 回填，往返收敛到 1~8 次（PG/SQLite RETURNING 逐行回填；MySQL LAST_INSERT_ID 连续性推算）。
- 失败判据：三方言真库逐行 ID 回填比对 + 触发器/自增连续性场景 + T5d 分配线。
- 风险（最高优先项）：自增连续性假设（MySQL `auto_increment_increment`）、触发器插入额外行、回填契约（ITM-325/556 语义：延迟回填 vs 立即回填的交互）。
