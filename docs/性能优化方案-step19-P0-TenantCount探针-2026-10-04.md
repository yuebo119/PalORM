> **结论：收档。产品租户 Count 路径的真实固定差 ~3µs（探针实测），PerfHub 显示的

## 一、探针设计（.ai/perf-probe/TenantCountDiag.cs，tenantcount 命令）

SQLite 文件库 WAL、同连接、2000 行表（probe_tc，列名契约与注解组合逐项照
bench_tenant）、播种 90% tenant=1 未删 + 5% tenant=2 + 5% 已删（播种核验 1800 行）。
每次迭代 = 1 个 COUNT 操作；预热 30 + 200 迭代。

| 格 | 形态 |
|---|---|
| ① | ADO 同款 SQL 逐字节（含引号列名与 @__tenant0），绑 long 1L |
| ①i | 同款绑 int 1（参数类型对照——SQLite 列亲和转换差） |
| ①n | 无引号列名变体（SQL 文本形态对照） |
| ② | 产品全路径：每迭代新会话 + WithTenant(1L) + CountAsync（保真夹具形态） |
| ②w | 会话复用（拆会话构造贡献；WithTenant 每次仍调用） |
| ③ | 产品无过滤实体基线（对齐 Count/perf_s1 形态） |
| ④ | ADO ① + 每迭代 new 会话后丢弃（纯会话构造增量交叉验证） |

  ADO 4.3µs，量级一致）
- 分配：② −① = +1416 B ≈ 会话 968 B + 管道 ~450 B（与 step13 拆账同源闭环）

捕捉不到批间系统性漂移。

## 四、判定

**收档。可砍段 ~2.9µs（构成：0.7 会话构造 + 2.2 管道小段累积）< 5µs 线。**

1. 13.4µs 上沿不是稳定产品差（三批摆动 + 探针同形态无法复现 >5µs）。
2. 真实差 ~3µs 的构成与 step17-P0 定案的"多小段累积"完全同构（每段 <1µs，无单段
   可砍），其中会话构造 968B 已由 F1 证伪（上界 72B < 200B 线）。
3. step18 的五个新判定项全部闭环：TenantCount 探针收档（本文件）、OrderBy 提案
   用户裁决关闭、TxBulkInsert/UpsertBatch SQLite ~9% 登记低优先、IncludeJoin/PG
   不同构登记、SessionBatchInserts 分配小项登记。

## 五、测量层登记（弱信号，非产品项）

PerfHub 短操作（50~70µs 量级）的 PalORM 臂存在 ±4~9µs 批间摆动而 ADO 臂稳定。
候选机制：每臂进场重建表 + 重播后的 WAL/页状态随臂序变化（ADO 先进、PalORM 后进），
20 轮中位数的样本量不足以平滑。**影响**：该量级操作的批间比值可信带约 ±8 个百分点
（如 TenantCount 1.08~1.21），跨批对比时以多批区间而非单批点值为准。不修改门禁
（比值阈值 1.3× 高于该摆动带），登记供解读后续批次时参考。
