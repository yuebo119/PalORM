## 三、BenchmarkDotNet 科学配置规范

### 3.1 配置层级

| 层级 | 配置 | 适用场景 | 统计可信度 |
|------|------|---------|:---:|
| 快速验证 | `launchCount=1, warmupCount=3, iterationCount=5` | 开发迭代、快速反馈 | ⚠ 低 |
| 标准基准 | `launchCount=3, warmupCount=5, iterationCount=10` | 正式报告 | ✅ 中 |
| 严格基准 | `launchCount=5, warmupCount=10, iterationCount=15` | 发版基线、CI 门禁 | ✅✅ 高 |

### 3.2 统计有效性判据

```
Error / Mean < 5%   → 统计有效（可用于正式报告）
Error / Mean 5-15%  → 可接受（需标注「环境敏感」）
Error / Mean > 15%  → 统计无效（必须提升配置或隔离噪声源）
```

### 3.3 当前违反规范的基准（P0）

| 基准 | Error/Mean | 问题 | 修复方案 |
|------|:---:|------|---------|
| PalORM_BulkInsert_10000 | **54%** | 批量操作离散度极高 | 提升至严格配置 + 固定 seed |
| PalORM_BuildSql_Simple | **14%** | nanosecond 级测量噪声 | 使用 `[NullGCMeasurement]` 或提升 iteration |
| PalORM_Delete_Physical | **29%** | 环境波动 | 标准配置 |

## 四、环境标准化

### 4.1 本地环境（开发机）

```bash
# SQLite（内存模式，最快）
dotnet run --project bench/PalORM.Benchmarks -c Release -- --filter '*SqliteBenchmarks*'
```

### 4.2 纯 Docker 环境（消除网络 RTT）

```bash
# 构建 + 运行（benchmark 客户端也在 Docker 里）
docker build -t palorm-bench .
docker run --rm --network=host \
  -e PALORM_BENCH_PG="Host=127.0.0.1;Port=5432;..." \
  palorm-bench dotnet run --project bench/PalORM.Benchmarks -c Release --no-build -- --filter '*PgBenchmarks*'
```

### 4.3 网络环境（真实生产场景）

```bash
# 本地客户端连远程数据库（含网络 RTT）
export PALORM_BENCH_PG="Host=192.168.x.x;Port=5432;..."
dotnet run --project bench/PalORM.Benchmarks -c Release -- --filter '*PgBenchmarks*'
```

### 4.4 CI 环境（性能门禁）

```yaml
# .github/workflows/perf-gate.yml（P1 待实施）
- 定时跑 SQLite 基准（每周）
- 与基线 JSON 对比，回归 >10% 失败
- 基线存储在 artifacts/
```

## 五、基线管理

### 5.1 基线格式

每次正式基准运行产出 JSON 基线，含：
- 时间戳 + 环境（CPU/OS/.NET 版本/Provider 版本）
- 每个基准的 Median + Error + Allocated
- 与上一版基线的差异百分比

### 5.2 回归判据

| 指标 | 回归阈值 | 动作 |
|------|:---:|------|
| Median | >10% | CI 失败，需人工评审 |
| Allocated | >20% | CI 警告 |
| Gen0/Gen1/Gen2 | >50% | CI 警告 |
