# PalORM v6.0 总体实施方案

> 状态：**定稿**（2026-09-28）· 需求真源：`docs/v6.0-requirements.md` · 任务分解：`docs/v6.0-tasks.md`
> 基线：v5.9.0（ee15a64）。本方案的全部行号引用以 5.9.0 为准，动工时以符号/成员名定位为准（行号会漂移）。

## 一、总览

**范围**：R1 投影 / R2 DefaultValue DDL / R3 Column 类型细化 / R4 唯一冲突异常 / R5 WithMetrics 转正 / R6 删除四项 / R7 ADR-M 重写与发布配套；G 向量 PoC 门控并行。

**实施顺序**（依赖与风险排序，非严格串行）：

```
Phase 0  准备（ADR-M 重写、CHANGELOG 未发布段、向量 PoC 启动）
Phase 1  R2 [DefaultValue] DDL        —— 最小独立首胜，消一类 PALORM017
Phase 2  R1 DTO 投影                  —— 核心功能，量级最大
Phase 3  R3 Column 类型细化 + R5 WithMetrics 转正（不同文件面，可并行）
Phase 4  R4 唯一冲突异常              —— 独立改动面
Phase 5  R6 删除四连 + 全仓清扫       —— 收尾做，避免中途扰动其他项的测试基线
Phase 6  R7 发布配套（ADR/迁移指南/LTS/CHANGELOG 转正）
门控线  G 向量 Phase 1 PoC → AOT 决策门 → 全量或 Raw 配方文档化
```

## 二、通用工程纪律（每 Phase 强制）

1. **快照基线**：凡动 SourceGen emit（R1/R2/R3），先 `PALORM_UPDATE_SNAPSHOTS=1 dotnet run`
   确认基线，diff 人工评审后才可提交（净语义变化，无意外漂移）。
2. **B29 PoC 驱动**：不确定的第三方 API（MySqlConnector 的 `MySqlErrorCode` 枚举名、
   Npgsql 的 `UseVector` 注册形态）先跑最小探针，以编译错误信息为准，不凭记忆写签名。
3. **验收锚点 = 撤修复即红**：每项先写锁定测试（修复前红、修复后绿），测试面板全绿不替代。
4. **pre-commit 三段**（secret-guard → stub-check → verify-ai-system --fast）自然拦截。
5. **每完成一项独立 commit**（`类型：描述` 格式），Phase 完成时 `dotnet build --no-incremental`
   全绿 + 技术债扫描。
6. **emit 变更清 obj/bin**（B8：增量构建复用旧 emit 导致 NRE）。

## 三、R1：DTO 投影物化

### 3.1 API 设计

```csharp
/// <summary>标记只读物化类型（DTO/投影）。源生成器为其生成 RowFactory 并注册；
/// 不生成写命令、不参与迁移 DDL。列映射按声明序（ordinal），契约同 ADR-A。</summary>
[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
public sealed class ProjectionAttribute : Attribute { }
```

用法：

```csharp
[Projection]
public class OrderListItem
{
    public long OrderNo { get; set; }
    public string UserName { get; set; } = "";
    public decimal Total { get; set; }
}

var rows = await session.QueryAsync<OrderListItem>(
    $"SELECT o.\"OrderNo\", u.\"Name\" AS \"UserName\", o.\"Total\" FROM ...");
```

### 3.2 实现路径

| 层 | 改动 |
|----|------|
| `Annotations.cs` | 新增 `[Projection]` |
| `PalORMGenerator.cs` | 新增第四条 `ForAttributeWithMetadataName("...ProjectionAttribute")` pipeline：只跑 RowFactoryEmitter + RegistryEmitter（注册行），**跳过** CommandFactoryEmitter / MigrationEmitter / 实体特性校验（租户/软删/乐观锁对投影无意义） |
| `RowFactoryEmitter` | 复用现有 ordinal 物化 emit（投影属性即可写属性，与实体读路径同构） |
| `PalORMAnalyzer` | 新诊断：`[Projection]` 与 `[Table]` 互斥（PALORM04x，编号顺延）；`[Projection]` 类型须满足 `class + new()` 约束形态 |
| 受益面 | `QueryAsync<T>` / `QueryFirstAsync<T>` / `QuerySingleAsync<T>` / `GridReader.Read<T>` / `StoredProcBuilder.QueryAsync<T>` 全部走 `PalORM_Runtime.RowFactories`，零改动自动支持 |

### 3.3 测试与验收锚点

- 生成端：快照（投影类型生成物形状：仅 RowFactory + 注册，无 Command/Migration 产物）。
- 集成（三方言）：join SQL → `QueryAsync<OrderListItem>` round-trip 断言；`GridReader`
  第二结果集映射到投影类型。
- 负例：`[Projection]` + `[Table]` 同标 → 编译期诊断；投影类型调 `From<T>()` → 编译期或运行时响亮失败（按 From 泛型约束现状定，动工时核实）。
- AOT：`AotTest` 三方言各加一条投影物化用例，publish 0 警告。
- **锚点**：不实现 `[Projection]` pipeline 时，`QueryAsync<OrderListItem>` 抛 "not registered"（红）；实现后 round-trip 通过（绿）。投影类型不出现在任何 MigrateAsync 产物中。

### 3.4 风险与缓解

| 风险 | 缓解 |
|------|------|
| 与 `[Table]` 注册冲突（同名/同类型双标） | 分析器互斥诊断拦截 |
| 投影属性含只读/复杂类型 | 沿用 RowFactoryEmitter 现有可写属性校验（编译期诊断） |
| 列序契约误用（错位静默换数据） | ADR-A 契约沿用：XML doc + 既有 PALORM 列序诊断若适用于投影则接入 |

## 四、R2：`[DefaultValue]` DDL 落地

### 4.1 设计

- `TableModel`：解析 `DefaultValueAttribute.Expression` 传递（当前丢弃）。
- `MigrationEmitter`：列定义追加 ` DEFAULT {Expression}`——表达式**原样**进三方言 DDL，
  不经转义、不做方言翻译（`[Computed]` ITM-541 同契约，XML doc 载明跨方言注意事项）。
- 列定义子句顺序：`col type DEFAULT expr NOT NULL`（标准顺序，动工时对齐三方言快照）。
- `PalORMAnalyzer`：PALORM017 移除 `[DefaultValue]` 分支（停报）；**新增互斥诊断**：
  `[DefaultValue]` 与 `[Computed]` 同属性（GENERATED 列不可有 DEFAULT）、
  `[DefaultValue]` 与自增 `[Key]` 同属性（语义无意义）——防生成非法 DDL。
- 插入路径**不变**：属性值照写（DDL-only，见需求边界）。

### 4.2 测试与验收锚点

- 快照：三方言 DDL 含 `DEFAULT` 子句（含含引号字符串字面量如 `DEFAULT 'pending'`）。
- 集成（三方言真库）：建表后 `INSERT` 省略该列（Raw SQL）→ 读回默认值生效；
  实体插入路径行为不变（属性值优先）。
- **锚点**：撤掉 Emitter 的 DEFAULT 追加 → 快照测试红 + 真库读不回默认值；恢复即绿。
  PALORM017 停报有专项测试（标注 `[DefaultValue]` 后诊断计数为零）。

### 4.3 风险与缓解

| 风险 | 缓解 |
|------|------|
| 表达式方言不合法（如 MySQL 不认 `gen_random_uuid()`） | ITM-541 同契约：调用方负责，XML doc 警示 + 跨方言部署注意事项 |
| 与 Computed/自增组合生成非法 DDL | 两条新互斥诊断（编译期拦截） |

## 五、R3：`[Column]` 类型细化

### 5.1 设计

- `TableModel`：解析 `Length` / `Precision` / `Scale` / `TypeName`（当前 null 占位）。
- `MigrationEmitter` 类型映射优先级：`TypeName` 直通 > Length/Precision 细化 > 现有默认映射。
- 方言行为：

| 方言 | 行为 |
|------|------|
| PostgreSQL | `VARCHAR(n)` / `NUMERIC(p,s)` 原生生效 |
| MySQL | `VARCHAR(n)`；n 超行宽上限（65535 共享）时**诊断警告**提示改用 TypeName 指定 TEXT 族——v1 不做自动分档 |
| SQLite | 类型亲和性：长度声明性不强制，原样写入（`VARCHAR(50)` 合法但引擎不截断）——文档化 |

- `PalORMAnalyzer`：PALORM017 移除 Column 架构参数分支（停报）；新增 Length/Precision/Scale
  值域诊断（非正数、Precision < Scale）。
- **闸门**：Length/Precision 先行；TypeName 直通若测试矩阵膨胀（快照量/方言组合超预期），
  拆出到后续 minor，不硬撑本版。

### 5.2 测试与验收锚点

- 快照：三方言含 Length/Precision 的 DDL 形状（SQLite 原样、PG/MySQL 约束）。
- 集成：MySQL 真库超宽插入报错（约束生效）；PG `NUMERIC(p,s)` 精度截断行为；
  SQLite 长度不截断（契约文档化的验证）。
- **锚点**：撤掉映射 → 快照红（回退到默认宽度类型）；恢复即绿。

## 六、R4：跨方言唯一冲突异常

### 6.1 API 设计

```csharp
/// <summary>唯一约束冲突（PG 23505 / MySQL 1062 / SQLite UNIQUE）。
/// InnerException 保留驱动原生异常；约束名不做跨方言抽象。</summary>
public sealed class UniqueConstraintViolationException : PalORMException
{
    internal UniqueConstraintViolationException(Exception inner)
        : base("Unique constraint violation. See InnerException for provider details.", inner) { }
}

// IDbProvider（与 IsTransient 同族的 static virtual）：
public static virtual bool IsUniqueViolation(Exception exception) => false;
```

三 Provider 覆写（**判定式以编译/反射探针为准，B29**）：

| Provider | 判定 |
|----------|------|
| PostgreSql | `PostgresException.SqlState == "23505"` |
| MySql | `MySqlException.ErrorCode == MySqlErrorCode.DuplicateKeyEntry`（枚举名待探针核实） |
| Sqlite | `SqliteException.SqliteErrorCode == 19 && Message 含 "UNIQUE constraint failed"`——SQLite 19 是笼统约束码（NOT NULL/FK/CHECK 同码），唯一判定依赖消息文本匹配 [推断]；消息格式不稳时的降级：文档化 SQLite 粒度为"约束冲突"，仍统一异常类型 |

### 6.2 包装点

写命令执行的最内层（`InsertAsync` / `SaveAsync` 的 insert 分支 / Bulk 逐条与单语句路径的
命令执行点）catch 判定 `IsUniqueViolation` → `throw new UniqueConstraintViolationException(ex)`。
落点原则：贴近命令执行、不进 Resilience 重试判定（唯一冲突非 transient，维持现状不重试）。
具体挂靠方法动工时按 DataSession.Crud / DataSession_Bulk 的实际结构定位（方案不预写行号）。

**不动的语义**：UpsertBatch/BulkMerge 自身的冲突处理逻辑不变（它们消费冲突而非抛出）；
读路径不包装（无害但语义泛化，不做）。

### 6.3 测试与验收锚点

- 三方言真库：建唯一索引 → 插入重复 → 断言 `UniqueConstraintViolationException` 类型 +
  `InnerException` 为原生异常类型 + `Source` 保持。
- 非唯一约束失败（NOT NULL 违反）**不**抛该类型（负例，SQLite 消息匹配的防误伤锚点）。
- **锚点**：撤掉包装 → 测试红（抛的是原生异常）；恢复即绿。

## 七、R5：`WithMetrics(name)` 转正

### 7.1 设计

- `QueryBuilder.WithMetrics(string name)`：`_metricsName` 字段存储（替换当前丢弃逻辑；
  校验保留）。
- 执行路径把 name 传入 `PalORMMetrics.Record`（签名加 `string? metricName = null` 参数，
  调用点全查）：有 name 时 TagList 追加 `palorm.query.name`，无 name 时不加
  （时间序列基数不变）。
- XML doc：**低基数警示**——name 应为静态业务名（如"订单查询"），禁止拼接动态值
  （高基数会打爆 Prometheus 侧时间序列）。

### 7.2 测试与验收锚点

- `MeterListener` 捕获：设 name 的查询 tag 含 `palorm.query.name=值`；不设的查询 tag 集合与
  现状逐位一致（基数不变锚点）。
- **锚点**：撤掉透传 → tag 断言红；恢复即绿。
