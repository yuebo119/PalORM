# 交叉基准基线（3 批窗口中位）

> 数据源：crossbench-20261026-112047.json · crossbench-20261026-114955.json · crossbench-20261026-120905.json
> 五臂：ADO.NET（地板）/ PalORM / Dapper / FreeSql / RepoDb，同批同数据同量具（两遍反序中位）。
> 读表：每格 = 时间 [对 ADO 倍数] / 内存 [对 ADO 倍数]；[1.00] = ±0.5% 持平带；≤0.67 或 ≥1.5 越线加粗；📌 = 越线待判读；⚠地板 = ADO 臂批间散布 >20%；🏆 = 该格最快臂。
> 口径与形态注记见 bench/crossbench/README.md 与 docs/adr/ADR-Q/R。

## 总览

五臂 × 三方言 × 14 操作（CRUD 与批量各两档、事务仅 2000 档）= **69 格**，3 批窗口中位。所有倍数均以 ADO.NET 手写 SQL 为基准 [1.00]。

### CRUD 单行与读（基准 = ADO [1.00]）

- 🥇 GetByKey SQLite：PalORM **0.77**（快 23%），FreeSql **4.72**（慢 372%，全方言最差 5.24）
- QueryAll MySQL 20000 分配：PalORM **0.91**（快 9%），Dapper 1.11（慢 11%）
- Insert SQLite：PalORM 0.98（快 2%），FreeSql **1.70**（慢 70%）
- RepoDb 单行与读：最差 1.47（慢 47%）——表达式物化与手写 SQL 同量级

### 批量处理（基准 = ADO [1.00]）

- 🥇 BulkDelete PG 20000：PalORM **0.39**（快 61%），分配 **0.10**（快 90%）
- 🥇 UpsertBatch PG 20000：PalORM **0.63**（快 37%），分配 **0.37**（快 63%）
- BulkInsert SQLite 20000：PalORM 1.02（慢 2%），Dapper 1.94（慢 94%），FreeSql **4.15**（慢 315%）
- BulkUpdate 三方言两档：PalORM 0.96~1.03，Dapper 最差 **3.74**（慢 274%）
- RepoDb 批量族：最好 BulkInsert MySQL **0.91**（快 9%），最差 BulkDelete SQLite **24.05**（慢 2305%）

### 事务（基准 = ADO [1.00]）

- PalORM 全项 0.93~1.15，最快 TxRollback PostgreSQL **0.93**
- FreeSql 最差 TxRollback SQLite **13.71**，Dapper 最差 TxRollback SQLite **3.88**
- EnumInserts SQLite 分配：PalORM 1.00（持平），FreeSql **8.41**（慢 741%）

## 表二：批量处理（三方言，两档）

> 胜场：PalORM 14 · ADO 9 · RepoDb 1 · Dapper 0 · FreeSql 0

### 测试项说明

| 操作 | 测什么 | 总评 |
|---|---|---|
| BulkInsert | 批量插入（SQLite 行预编译 / PG COPY / MySQL BulkCopy） | PalORM 与 ADO 同形态贴平；RepoDb 走官方 BulkOperations（COPY/LOAD DATA 经 pseudo 表）接近地板；Dapper/FreeSql 批量路径全方言偏慢 |
| BulkUpdate | 批量更新（SQLite 逐条裹事务 / PG UPDATE FROM VALUES / MySQL CASE WHEN） | PalORM 三方言与 ADO 同形态贴平；RepoDb 在 MySQL 用 BulkOperations 的 pseudo 表、PG/SQLite 用 Core UpdateAll 逐行，两条路径都明显偏慢；Dapper/FreeSql 无集合式封装 |
| BulkDelete | 批量删除（SQLite json_each 单参数 / PG = ANY 数组 / MySQL IN 分批） | PG 数组形态快于 ADO 的 IN 占位符；SQLite json_each 与 MySQL 分批接近地板；RepoDb 的 DeleteAll 按主键逐个构造 QueryGroup，分配与时间都显著偏高 |
| UpsertBatch | 批量 UPSERT（ON CONFLICT / ON DUPLICATE KEY） | PG 数组形态快于 ADO 与其余臂；SQLite 各臂同形态贴平；RepoDb 在 MySQL 用 BulkMerge（pseudo 表）、PG 因 BulkMerge 上游缺陷退回 MergeAll；Dapper/FreeSql 偏慢 |
