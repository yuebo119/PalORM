Build 组读法（重要）：ADO.NET / Dapper 两臂的BuildXxxSql 只是返回一条预先写好的字面量 SQL，测的是「不构建」的下限；PalORM 臂测的是 From<T>()/Where/OrderBy/Take 链式构建 + 方言引用符 + DryRun 出参的完整开销。两者不是同一件事，该组的差值应读作「ORM 构建税」，不是「PalORM 查询慢 20 倍」——查询快慢看 CRUD/Query 组。
口径：时延取中位数（同轮对照）；全路径——被测动作内部包含 SQL 构建（From<T>()/Where/BuildSql）→ 执行 → 物化，测量引擎不剥离任何段；种子数据的生成在测量前完成，不计入时延。分配为 GC.GetTotalAllocatedBytes 精确计数（确定性指标，复现性优于 1%）；堆峰为 GC.GetGCMemoryInfo().HeapSizeBytes 采样——.NET 无「操作期间曾达到的最大值」API，故标注为采样堆峰而非精确峰值，它含 ORM 内部与数据对象的真实驻留；Error/Mean > 5% 标黄（量具自检参考，非失败）。

⑥ 说明与未覆盖维度

本次运行：116 项测量，其中 29 项 Error/Mean > 5%（量具自检参考，非失败）。耗时 202 秒。
数据集：S1 Narrow（主键 + 4 数据列），种子由行号确定性派生——三次测量库内容逐位相同。
三实现同连接：ADO.NET / Dapper / PalORM 复用同一条已打开连接（建连口径一致，否则比值被污染，见 lessons B76）。
会话生命周期：PalORM 臂按操作新建 DataSession——与 Dapper 的无状态扩展方法对等；会话不释放，因为 DisposeAsync 会关闭三实现共用的那条连接。若应用层是「一个请求一个会话、用完后释放」，会话构建开销会被摊薄，PalORM 的点查数字会更好。
Build 组不是同类对比：ADO.NET / Dapper 返回预写字面量，PalORM 真的在构建 SQL，该组差值读作「ORM 构建税」而非查询快慢。
未覆盖维度：方言 DDL 差异（三方言表结构同构，未测 JSON/数组/枚举等方言特有类型）；连接池行为（PerfHub 用单连接，池参数不在本报告范围）；长时衰减（单次运行无衰减数据，需连续多轮对比）；并发态分配（多线程下 GetTotalAllocatedBytes 被干扰，不测，见 lessons B74）。
