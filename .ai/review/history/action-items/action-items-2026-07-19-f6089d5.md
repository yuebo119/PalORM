## 整改建议（修复前必读）

### ITM-605（P2）修复要点

**根因**：ITM-603 守卫只加在 `DataSession.CreateAsync`（行 78-87，连接重试路径），未加在 `ResilienceExecutor.ExecuteAsync`（行 75，命令重试路径）——两路径独立调用 `RetryBackoff`。

**修复方向**：在 `Resilience.cs:75` 前加守卫，或更优——把守卫**包装到 ResilienceExecutor 构造函数**（行 41 `_backoff = options.RetryBackoff ?? GetDefaultBackoff`）：

```csharp
_backoff = attempt =>
{
    TimeSpan delay = (options.RetryBackoff ?? GetDefaultBackoff)(attempt);
    if (delay < TimeSpan.Zero)
        throw new InvalidOperationException(
            $"DbOptions.RetryBackoff(attempt={attempt}) returned negative {delay}.");
    return delay;
};
```

这样**所有走 ResilienceExecutor 的路径**（CreateAsync 的 ResilienceExecutor + 命令重试）统一覆盖，且 DataSession.CreateAsync:78-87 的守卫可移除（避免重复）。

### ITM-606（P2）修复要点

**根因**：`DataSession.UseTransaction`（行 580）先做 `ReferenceEquals(tran.Connection, _conn)`——已 dispose 事务 `tran.Connection == null`，不等于 `_conn`，先抛"事务必须属于主连接"。

**修复方向**：交换两段顺序，先查 disposed：

```csharp
public DataSession<TProvider> UseTransaction(DbTransaction? tran)
{
    // ITM-606: 先查 disposed——tran.Connection == null 时 ReferenceEquals 永远 false 会遮蔽
    if (tran is not null && tran.Connection is null)
        throw new ArgumentException("Cannot use a disposed transaction.", nameof(tran));
    if (tran is not null && !ReferenceEquals(tran.Connection, _conn))
        throw new ArgumentException("事务必须属于当前 DataSession 的主连接。", nameof(tran));
    _operationState.UseTransaction(tran);
    return this;
}
```

### ITM-607（P2）修复要点

**根因**：`PalORMAnalyzer.cs:265` 仍用 `type.GetMembers().OfType<IPropertySymbol>()`，ITM-601 整改时漏改。

**修复方向**：改为 `SourceGenerationValidation.EnumerateMappedProperties(type)`（与 PALORM001/002/014/018/021 一致）。
