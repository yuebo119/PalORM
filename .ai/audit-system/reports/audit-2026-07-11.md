## 1. 结论

当前仓库不能支持“111 API 全部实现”“三 Provider 全链路 AOT 安全”“116/116 全部通过”“构建 0 警告”“文档与实现完全对齐”等声明。

本轮确认 1 项 P0、15 项 P1、8 项 P2。综合评分从上轮报告的 96.4 降至 40.2。该变化主要来自审计深度修正，不代表这些问题均由最近提交引入。最近 5 个提交以文档和注释为主，多数问题在此前实现中已经存在，但旧报告没有覆盖。

最高优先级事项：

1. 版本控制中的测试环境脚本含数据库凭据并会将完整连接串输出到终端。必须先轮换凭据，再清理仓库和历史。
2. `SaveAsync`、`[ConcurrencyCheck]`、读写分离、软删除、拆分查询等核心数据语义与文档不符。
3. `OwnedJson` 使用反射型 System.Text.Json 重载，不能证明 Native AOT 安全。
4. 多个公共字符串入口直接进入 SQL 结构，存在标识符或注释注入风险。

## 7. 发现清单

### P0

#### AUD-001：版本控制中存在数据库凭据，并输出完整连接串

- 位置：`scripts/set-test-env.sh:4-5`、`scripts/set-test-env.sh:7-8`
- 证据：脚本包含两套硬编码数据库连接信息，并通过 `echo` 输出完整连接串。文件自提交 `aa3d07c` 起受 Git 跟踪。
- 影响：凭据可能已进入本地日志、终端历史、Git 克隆和远端缓存。
- 处置顺序：先轮换数据库凭据；再将脚本改为只读取环境变量且不输出值；最后评估清理 Git 历史。不得只删除当前文件后继续使用原凭据。

### P1

#### AUD-002：`SaveAsync` 对已有自增主键实体不能实现 UPSERT

- 位置：`src/PalORM.Core/DataSession.cs:206-245`
- 根因：生成的 Insert binder 排除自增主键，构造的 INSERT 也排除主键，但冲突目标仍是主键。
- 触发：`SaveAsync(new User { Id = 1, ... })`。
- 影响：SQLite/PG 会插入新 ID；MySQL 在无其他唯一键冲突时也会插入新行。README `68-72` 的更新示例不成立。
- 测试缺口：现有测试只覆盖“保存新实体”。

#### AUD-003：`[ConcurrencyCheck]` 生成错误 SQL，且冲突不抛异常

- 位置：`src/PalORM.SourceGen/CommandFactoryEmitter.cs:121-135`、`:164-190`，`src/PalORM.Core/DataSession.cs:129-137`
- 生成证据：`VersionedEntity` 当前生成 `SET version` 两次，并用同一当前值作为 SET 和 WHERE 参数。
- 影响：没有旧版本值、没有原子递增、0 行更新不抛 `ConcurrencyConflictException`，无法阻止丢更新。
- 测试缺口：`AdvancedTests.cs:14` 断言 `rows >= 0`，即冲突返回 0 也会通过。

#### AUD-004：读写分离创建关闭的读连接，并在多个路径泄漏

- 位置：`src/PalORM.Core/QueryBuilder.cs:196-197`、`src/PalORM.Core/QueryBuilderExtensions.cs:19-65`、`:121-140`
- 根因：`ForRead()` 只调用 Provider `CreateConnection`，没有 `OpenAsync`。
- 影响：标准 ADO.NET Provider 执行时会报连接关闭。只有 `ToListAsync` 的 finally 尝试释放；`FirstAsync`、`FirstOrDefaultAsync`、`QueryMultipleAsync`、`ExecuteNonQueryAsync` 没有释放读连接。
- 附加问题：`.ForRead().ForWrite()` 只改布尔值，仍使用读连接。

#### AUD-005：`CreateAsync` 重试失败路径不释放连接

- 位置：`src/PalORM.Core/DataSession.cs:42-74`
- 根因：每次 attempt 在 try 内创建连接，打开、PRAGMA 或注册表验证抛异常后直接进入 catch，连接没有 Dispose。
- 影响：重试会放大连接池、socket 或 native handle 泄漏。
- 附加问题：`MaxRetries=1` 时第一次失败立即抛出，实际没有重试；实现与属性名称和文档语义不一致。

#### AUD-006：软删除没有自动查询过滤，且删除 SQL 只适用于 SQLite

- 位置：`src/PalORM.Core/DataSession.cs:107-110`、`:140-155`
- 证据：`From<T>()` 只自动附加租户过滤，没有为 `[SoftDelete]` 添加 `deleted_at IS NULL`。
- 方言问题：统一使用 `datetime('now')`，PG 和 MySQL 不支持该表达式。
- 影响：普通查询会返回已删除行；PG/MySQL 软删除执行失败。README `219-235` 与实现冲突。

#### AUD-007：JOIN 插值产生占位符但不绑定参数

- 位置：`src/PalORM.Core/QueryBuilder.cs:154-161`
- 根因：三个 JOIN 调用 `FormatFormattableSql`，但没有把 `onClause` 实参加入 `_parameters`。
- 影响：带值条件的 JOIN 生成 `@pN` 后执行时报缺少参数。
- 测试缺口：现有 JOIN 测试只使用列与列比较，没有插值值。

#### AUD-008：`QueryMultipleAsync` 未转换 FormattableString 占位符

- 位置：`src/PalORM.Core/QueryBuilderExtensions.cs:121-129`
- 根因：`cmd.CommandText = sql.Format` 保留 `{0}`，同时参数名却为 `@pN`。
- 影响：只要传入插值参数即产生语法错误。执行失败前创建的命令也没有 finally 释放。
- 测试缺口：现有测试 SQL 没有插值参数。

#### AUD-009：拆分查询的 JOIN 标记数组与子句数组不同步

- 位置：`src/PalORM.Core/QueryBuilder.cs:25-27`、`:152-176`、`:214-237`
- 根因：只有三个显式 Join 方法向 `_isJoinClause` 添加标记，WHERE、Include、CTE 等直接写 `_clauses`。
- 影响：`AsSplitQuery()` 下可能跳过错误子句或访问越界。README 的 Include + AsSplitQuery 示例会触发该路径。
- 测试缺口：现有 SplitQuery 测试没有任何 JOIN 或 Include。

#### AUD-010：`ThenInclude` 生成字面量省略号 SQL

- 位置：`src/PalORM.Core/QueryBuilder.cs:175-176`
- 证据：ON 条件右侧直接写为 `...`。
- 影响：任何实际执行都会产生无效 SQL。该 API 仍计入 111 项已完成清单。

#### AUD-011：公共熔断器每次调用重建状态

- 位置：`src/PalORM.Core/DataSession.cs:507-525`、`src/PalORM.Core/Resilience.cs:15-17`
- 根因：`ExecuteWithResilience` 每次 new `ResilienceExecutor`，失败计数和打开时间不会跨调用保留。
- 影响：公开 API 不能实现连续失败后的快速失败。直接测试 `ResilienceExecutor` 不能证明 DataSession API 正确。

#### AUD-012：跨程序集 SourceGen 注册表互相覆盖

- 位置：`src/PalORM.SourceGen/RegistryEmitter.cs:19-127`、`src/PalORM.Core/PalORM_Runtime.cs:10-47`
- 根因：每个消费程序集的 ModuleInitializer 都替换整组进程级静态 FrozenDictionary，而不是合并或按程序集隔离。
- 影响：实体分布在多个程序集时，后执行的初始化器会使其他程序集实体变成“未注册”。
- 外部依据：Microsoft Learn 明确说明多个 ModuleInitializer 的调用顺序确定但未指定，不能作为业务覆盖顺序保证。

#### AUD-013：OwnedJson 不是全链路 Native AOT 安全路径

- 位置：`src/PalORM.SourceGen/CommandFactoryEmitter.cs:19-21`、`:193-198`，`RowFactoryEmitter.cs:61-67`
- 根因：生成代码调用接受 `JsonSerializerOptions` 的 `Serialize<T>` / `Deserialize<T>` 重载，没有 `JsonSerializerContext` 或 `JsonTypeInfo<T>`。
- 影响：裁剪或关闭反射序列化后可能运行失败。生成器又输出无范围 `#pragma warning disable`，会隐藏生成代码诊断。
- 测试缺口：OwnedJson 测试属性是 `string`，三套 AOT 项目均未覆盖 OwnedJson。
- 外部依据：https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/reflection-vs-source-generation

#### AUD-014：多个公共字符串入口可进入 SQL 结构

- 位置：`src/PalORM.PostgreSql/PgNotificationListener.cs:53-59`、`QueryBuilder.cs:178-203`、`DataSession.cs:376-390`
- 入口：LISTEN channel、`Tag`、`WithMetrics(name)`、`WindowOver(func, over)`、CTE name、保存点 name。
- 根因：这些内容属于标识符、注释或 SQL 结构，不能通过值参数化处理；当前没有严格白名单或无条件标识符引用。
- 影响：当调用方传入不可信值时，可造成语法注入、多语句注入或可控命令失败。
- 说明：`Raw` 是显式逃生舱，不在本项统计；其他 API 文档没有标为原始 SQL 入口。

#### AUD-015：MySQL `batchSize <= 0` 可导致不前进循环

- 位置：`src/PalORM.MySql/MySqlProvider.cs:34-64`
- 根因：循环增量直接使用 `batchSize`，MySQL Provider 没有像 SQLite/PG 一样归一化非正值。
- 影响：非空集合且 batchSize 为 0 时循环不结束；负值会向错误方向移动。

#### AUD-016：Schema 校验在 PG/MySQL 读取错误列

- 位置：`src/PalORM.Core/DataSession.cs:270-295`、`src/PalORM.PostgreSql/PostgreSqlProvider.cs:22-24`、`src/PalORM.MySql/MySqlProvider.cs:22`
- 根因：校验固定读取 `reader.GetString(1)`。SQLite PRAGMA 的列名在索引 1；PG information_schema 和 MySQL SHOW COLUMNS 的列名在索引 0。
- 影响：PG/MySQL 会把数据类型当列名，产生全量误报。

### P2

#### AUD-017：`WithPool` 配置没有生产消费者

- 位置：`src/PalORM.Core/DbOptions.cs:27-34`、`:66-68`，`DataSession.cs:39-49`
- 证据：池参数只存入 record，创建连接时仍只传原连接串。测试只验证属性变更。

#### AUD-018：Tracing、Metrics、Prepared 与名称不符

- 位置：`src/PalORM.Core/QueryBuilder.cs:193-203`、`QueryBuilderExtensions.cs:19-40`、`PalORMMetrics.cs:5-30`
- `WithTracing` 只添加 SQL caller 注释，没有 Activity/span。
- `WithMetrics(name)` 只添加 SQL 注释，name 没有传入指标；Counter 方法无生产调用者。
- `AsPrepared` 只缓存 SQL 字符串，没有 Prepare、命令池或参数模板；后续修改 builder 还会继续使用旧 SQL。

#### AUD-019：`BulkMergeAsync` 和 `SeedAsync` 不满足名称语义

- 位置：`src/PalORM.Core/DataSession_Bulk.cs:75-81`
- `BulkMergeAsync` 直接调用普通 BulkInsert，没有冲突更新。
- `SeedAsync` 直接普通插入，重复执行会重复数据或触发唯一键异常，不幂等。

#### AUD-020：取消和回滚错误语义不可靠

- 位置：`src/PalORM.Core/DataSession.cs:279-295`、`:537-568`，`DataSession_Bulk.cs:27-44`，`QueryBuilderExtensions.cs:82-118`
- `ValidateSchemaAsync` 和 `HealthCheckAsync` 捕获所有异常，将调用者取消转成普通结果。
- 错误路径使用原始、可能已取消的 token 回滚，可能掩盖原始异常并使回滚未发送。

#### AUD-021：`DisposeAsync` 可因拦截器异常跳过连接释放

- 位置：`src/PalORM.Core/DataSession.cs:590-603`
- 任一拦截器 `Dispose()` 抛出后，连接关闭和释放不会执行；`_disposed` 已设为 true，第二次释放也无法补救。

#### AUD-022：测试和门禁不能支撑“全部通过”声明

- `dotnet test PalORM.slnx --no-restore`：74/78 集成测试通过，4 项因外部数据库不可达失败；不能写成当前 116/116。
- Release 全量构建：0 错误、1,289 警告。测试和 benchmark 项目覆盖了全局 `TreatWarningsAsErrors=true`。
- `scripts/gate-check.sh`：G1 后在 G2 零命中 grep 的命令替换中被 `set -euo pipefail` 提前终止，未完成 G2-G23。
- G1 将可继承的基础异常类算作“必须 sealed”，规则本身与异常继承体系冲突。
- `scripts/stub-check.sh` 因 `DataSession.ForWrite() => this` 失败。

#### AUD-023：AOT 验证不是 SourceGen 到运行时的完整链路

- 三个 AotTest 项目均编译手工提交的 `.g.cs`，没有引用 SourceGen analyzer。
- SQLite 覆盖 Insert + Query 并成功运行原生二进制。
- PG/MySQL 只覆盖原始 Execute + Scalar，没有覆盖实体 CRUD，且本轮未运行原生二进制。
- CI 实际发布的是 Integration.Tests，不是三个独立 AotTest 项目，也没有运行发布后的二进制。

#### AUD-024：文档和项目元数据多处冲突

- `docs/API参考.md` 中大量实现行号已漂移，例如 `DiffAsync<T>`、`From<T>`、`Where`、`InnerJoin`、`QueryAsync`。
- README 声明 AGPL v3；`Directory.Build.props` 的 NuGet 许可证是 MIT。
- AOT 指南开头称三 Provider 全部通过，状态表又称 PG/MySQL 需验证，并建议抑制 IL2090；这与“零 IL 抑制”和项目强制规则冲突。
- 审计提示词仍引用不存在的 `docs/STANDARDS.md`、旧设计路径以及 112 API、295 坑口径。

## 9. 风险预判

| 因子 | 权重 | 分值 | 依据 |

最可能的近期故障：

1. README 示例驱动用户使用 SoftDelete、ForRead、SaveAsync 或 Include + SplitQuery 后直接遇到错误数据或运行时异常。
2. 多实体程序集接入后，启动顺序变化导致部分实体间歇性“未注册”。
3. 发布 Native AOT 后首次使用对象型 OwnedJson 才暴露序列化元数据缺失。
4. 已暴露的测试数据库凭据被继续使用或进入更多日志。

## 10. 建议修复顺序

1. 安全止血：轮换脚本中的凭据，停止输出连接串，评估 Git 历史清理。
2. 收缩承诺：在 README、AOT 指南、API 参考中暂时标注未验证或未完成能力，统一许可证。
3. 修复核心语义：SaveAsync、ConcurrencyCheck、CreateAsync 生命周期、ForRead/ForWrite、SoftDelete。
4. 修复 QueryBuilder 不变量：统一 clause + kind 数据结构，补 JOIN 参数、QueryMultiple 插值、ThenInclude、分页参数测试。
5. 重构注册协议：使多程序集注册可合并或显式注册，增加两个实体程序集的运行测试。
6. 建立 STJ source-generation OwnedJson 路径，并在独立 AOT 项目中使用对象图实测。
7. 修复门禁脚本，使每项检查即使零命中也继续执行；CI 运行三 AOT 项目并执行原生二进制。
8. 逐项回填行为测试。禁止用“非 null”“大于等于 0”“能编译”作为功能完成证据。
